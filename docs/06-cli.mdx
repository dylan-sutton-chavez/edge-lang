# CLI

This page covers the `interpreter` CLI, its commands, a project from its first file to a build, packages, grants, actors and a CLI of your own. The CLI runs the programs of any runtime on macOS, Linux and WSL. [Install](./01-overview.mdx#install) installs it, and the examples run Lox from the `lox.wasm` it downloads. A minor release may change the commands and flags, which [Stability](./09-stability.mdx#exceptions) does not cover yet.

## The runtime

The CLI holds no runtime, and a command with none fails before it reads a program. `runtime` in `interpreter.json` names the runtime's `.wasm`, by path or by a URL that pins its bytes with `#sha256-<64 hex>`. `--runtime <file>` names one for a single command, and `INTERPRETER_RUNTIME` names one for every project that declares none.

```json
{ "runtime": "./lox.wasm" }
```

### wasm or native

A runtime runs as a `.wasm` unless the project says otherwise. It is the module the JS host loads, so a program gives the same output in a page and in a terminal, and it reaches the outside only through the host modules its grants allow.

A native runtime is the same crate built as a `.so`, `.dylib` or `.dll`, as `make native` builds Lox's to `target/native/`. `"runtime": { "native": "./lox.dylib" }` or `--runtime-native <library>` names one. It runs with no sandbox, so use one only for a runtime you build yourself.

| | `.wasm` | Native |
|---|---|---|
| Sandbox and grants | Held | None |
| Plugins and the eval groups of [actors](#actors) | Yes | No |
| Loads from | A path or a pinned URL | A local path |
| Speed | Compiled ahead for the machine | Faster, with no sandbox to cross |

Every command on a native runtime prints one warning to stderr, and so does a bundle that carries one. The runtime runs in a child process, so a panic or a crash in it fails the run with an error.

```text
warning: native runtime, it runs outside the sandbox and the grants of interpreter.json do not hold it
```

## Commands

| Command | Does |
|---|---|
| `interpreter run <file>` | Runs a script, a `.interpreter` bundle, stdin, or `-c <code>`. `--web` runs it in headless Chrome on the JS host |
| `interpreter build` | Packs the project into `app.interpreter`. `--app` writes a standalone binary, `--web` a `dist/` folder for the browser, and `--out` names the output |
| `interpreter test [path]` | Runs every `*_test.lox` file in a fresh session, and `--web` runs them on the JS host |
| `interpreter init [name]` | Creates a project with `main.lox`, `interpreter.json` and an `index.html`. `--bare` leaves out the page |
| `interpreter add <name>=<source>` | Declares an import in `interpreter.json`, by URL or by path |
| `interpreter remove <name>` | Removes an import |
| `interpreter lock` | Downloads every URL import once and pins its digest in `interpreter.lock` |
| `interpreter serve` | A dev server with live reload, on `127.0.0.1:5173` unless `--host` and `--port` say otherwise, and `--open` opens it in a browser |
| `interpreter actor <file>` | Runs a pool of [actors](#actors) from an `actor.yml` |
| `interpreter uninstall` | Removes the binary the install script placed, its PATH entry and its cache, and offers to remove the Chromium `--web` downloaded. A binary from `cargo install` goes with `cargo uninstall interpreter` |

| Flag | Commands | Sets |
|---|---|---|
| `--memory <MB>`, `--ops <n>` | `run`, `test` | The limits of a run, with memory in MiB |
| `--events <file>` | `run` | One event per line for `receive()` |
| `--preempt <n>`, `--save-state <file>`, `--restore-state <file>` | `run` | Stop every `n` back-edges, and save or resume a run |
| `--manifest <file>` | every command | The manifest in place of `./interpreter.json` |
| `--runtime <file>`, `--runtime-native <library>` | every command | The runtime in place of the one `interpreter.json` names |

## A project

`interpreter init` creates a project on the runtime `--runtime` names and writes its path into `interpreter.json`.

```text
$ interpreter init hello --runtime lox.wasm
created hello/
$ cd hello
```

`main.lox` imports `stars.lox` by its path.

```lox stars.lox
// a bar of n stars for a chart in the terminal
fun stars(n) {
    var bar = "";
    for (var i = 0; i < n; i = i + 1) bar = bar + "*";
    return bar;
}
```

```lox main.lox
var stars = import("./stars.lox").stars;

print "lox " + stars(3);
print "sdk " + stars(5);
```

```text
$ interpreter run main.lox
lox ***
sdk *****
```

A test fails when its run ends with an error or a status other than 0, and then `interpreter test` exits with 1.

```lox stars_test.lox
var stars = import("./stars.lox").stars;

fun expect(got, want) {
    if (got != want) {
        print "got '" + got + "' for '" + want + "'";
        exit(1);
    }
}

expect(stars(0), "");
expect(stars(2), "**");
```

```text
$ interpreter test
(successful) stars_test.lox
```

`interpreter build` packs the scripts, the manifest, every import and the runtime into one bundle, `app.interpreter`, that runs wherever `interpreter` is installed.

```text
$ interpreter build
packed app.interpreter (4 files)
$ interpreter run app.interpreter
lox ***
sdk *****
```

## Packages by URL

A package is anything a project imports under a name, by path or by a URL to a `.lox` module, a `.wasm` plugin or a `.interpreter` bundle, such as one a GitHub release attaches. This one takes a module from this repo at a fixed commit.

```text
$ interpreter add util=https://raw.githubusercontent.com/dylan-sutton-chavez/interpreter/da9bda4365e8e7f62a7f9449964fef94874c51e5/docs/util.lox
+ util       https://raw.githubusercontent.com/dylan-sutton-chavez/interpreter/da9bda4365e8e7f62a7f9449964fef94874c51e5/docs/util.lox
updated interpreter.json, run interpreter lock to pin it
$ interpreter lock
wrote interpreter.lock
```

```lox main.lox
var util = import("util");

print util.greet();
```

```text
$ interpreter run main.lox
hello from a package
```

`run`, `test` and `build` refuse any bytes but the ones `interpreter.lock` pins, so run `interpreter lock` after each change to `interpreter.json` and commit `interpreter.lock` with the code. An import can also pin its bytes in the URL with a `#sha256-<64 hex>` fragment.

A package describes itself in its own `interpreter.json`.

| Field | Rule |
|---|---|
| `name` | Up to 40 lowercase letters, digits and single hyphens, starting with a letter. Never `all`, `main` or `eval` |
| `version` | `major.minor.patch`, each part 0 to 99 with no leading zeros |
| `description` | One line, up to 60 characters |
| `repository` | An `https` URL of up to 256 characters |
| `docs` | A folder of `.mdx` pages that `interpreter build` packs with the package |
| `interpreter` | The lowest release of `interpreter` the package runs on, which an older one refuses |
| `extends` | A folder whose `interpreter.json` lends its imports to the names this one lacks |

## Grants

A program reaches the outside only through host modules. The CLI serves two and the JS host serves `net`.

| Module | Calls | Scope of a grant |
|---|---|---|
| `net` | `request(method, url, headers, body, inflate, timeout)` gives an id, then `response(id)`, `read(id)` and `close(id)`. `connect(url)` and `send(id, data)` for WebSockets | `net:<host>`, or `net:<host>/<prefix>` for the paths under it |
| `files` | `open(path, inflate)` gives an id, then `read(id)` and `close(id)` | `files:<file>`, or `files:<dir>/` for every file below it |

The root `interpreter.json` grants them in `permissions`, which maps a holder to entries written `module:scope`.

| Holder | Holds |
|---|---|
| `main` | The project's own code |
| An import name | That package |
| `all` | The project and every package it imports |
| `eval` | The most a bundle an [eval group](#actors) runs may hold |

A package lists what it needs in its own `interpreter.json` and passes on only what its importer gave it. A call outside its grant raises before anything leaves the process.

```lox-manifest
{ "permissions": { "main": ["net:api.example.com"] } }
```

```lox
var net = import("net");
net.request("GET", "https://other.example/");
```

```output
'main' has no net:other.example, interpreter.json grants it net:api.example.com
[line 2] in script
```

## Actors

`interpreter actor <file>` runs a pool of actors from an `actor.yml`. Its `groups` map each name to what the actors of that group run, and its `runtime` key sets the pool.

| Group key | Sets |
|---|---|
| `run`, `code`, `eval` | What the group runs, a script or a project folder by path, a body inline, or with `eval: true` each message it receives. A group takes one of the three |
| `replicas` | How many actors run the group, 1 unless it is an eval group, which runs 4 |
| `seed` | The messages that start the group's actors |
| `retry` | How many times a message that crashes an actor runs again on another before it is dropped |
| `limits` | `memory` in MiB, `ops` and `preempt` for each run, and `timeout` for an eval run, 1 to 300 seconds with 10 by default |
| `out` | Where the group prints, `stdout`, `null` or `file://<path>` |

| Key under `runtime` | Sets |
|---|---|
| `max_actors` | The most actors the pool holds at once |
| `schedulers` | `auto` for one thread per core, or a count of threads |
| `listen` | The address that turns the pool into a live server, which takes a message for a group at `POST /pub/<group>` |
| `control` | The loopback address of the server's HTTP control endpoint |
| `durable` | The log the server keeps across restarts, `actor.wal` beside `actor.yml` unless set |

An eval group runs untrusted code. Each message is a program of its own, a source or a bundle, run in a fresh session with no `send`. A live server takes one at `POST /eval/<group>` and answers with what it printed or the error it ended with. A source holds no grant, and a bundle holds what its own `interpreter.json` grants within what the pool's grants the `eval` holder.

## A CLI of your own

`interpreter::cli` is a kit behind the `cli-*` features. A `Kit` takes a runtime and the commands you wire, each behind a feature. The `interpreter` binary is `Kit::per_project`, which runs whatever runtime a project names, and a runtime of yours gets a CLI of its own with `Kit::new`. With no arguments this one prints its help.

```rust standalone_crate
use interpreter::cli::cmd::{Run, Test};
use interpreter::cli::{Engine, Kit};

// lox runs linked into this binary and meters its memory through this allocator
interpreter::allocator!();

fn main() {
    Kit::new("calc", "0.1.0", Engine::native(&interpreter_lox::RUNTIME))
        .title("A CLI for calc programs")
        .command(Run)
        .command(Test)
        .main()
}
```

`Engine::native` links the runtime into the binary, with no `.wasm` or library to load. `Engine::wasm(bytes, RUNTIME.descriptor())` loads its `.wasm` instead, which also lets the binary load plugins, and the descriptor comes from the runtime with its extension and error classes filled in. `Kit::engine` gives back the engine a kit runs.

`.module(...)` serves a host module such as `interpreter::cli::host::Net` or `interpreter::cli::host::Files`. `.access(Arc::new(interpreter::cli::Perms))` holds each package to its grants and declares the `permissions` field it reads, so a composition wires no field for it. `.fields(interpreter::cli::MANIFEST_FIELDS)` checks the manifest fields of [a package](#packages-by-url), and `.field(interpreter::cli::DOCS_FIELD)` adds `docs`. A field declared twice keeps one entry under its name.

A host module of your own implements `interpreter::cli::host::HostModule`. It gets the grants of its caller as an opaque `Held`, which it reads with `reach`, `need` and `scopes`, and it fails a call with a `Fault` built by `Fault::invalid`, `Fault::denied`, `Fault::failed` or `Fault::runtime`. `interpreter::cli::host::is_plain_path` tells a path that stays under its folder.

The example takes the engine and Lox from git, as [Lox](./01-overview.mdx#lox) shows, and a runtime of yours needs `interpreter = { version = "1", features = ["cli-run", "cli-test"] }`.

| Feature | Command or part |
|---|---|
| `cli` | Every part below, the set the `interpreter` binary wires |
| `cli-kit` | The `Kit` alone with no command |
| `cli-run`, `cli-test`, `cli-build`, `cli-init`, `cli-serve`, `cli-uninstall` | The command of that name |
| `cli-actors` | `actor`, with the live server an actor pool becomes |
| `cli-packages` | `add`, `remove` and `lock` |
| `cli-net`, `cli-files` | The host modules for requests and sockets, and for local files |
| `cli-perms` | Grants |
| `cli-docs` | The pages a package ships, held to the docs convention |
| `cli-web` | `--web` runs on headless Chrome |
| `cli-wasm` | Runtimes and plugins as `.wasm` |
| `cli-library` | Runtimes as native libraries a child process loads |

A build with `coverage` beside any `cli-*` feature writes the lines each native run executed to the file `INTERPRETER_COVERAGE` names.
