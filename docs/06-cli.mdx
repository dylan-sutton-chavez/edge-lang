# CLI

The `interpreter` CLI runs the programs of any runtime on macOS, Linux and WSL. It holds no runtime of its own, and a project names the one it runs on. [Install](./01-overview.mdx#install) builds it, and the examples below run Lox from `lox.wasm`.

## The runtime

`runtime` in `interpreter.json` names the runtime's `.wasm`, by path or by a URL that pins its bytes with `#sha256-<64 hex>`. `--runtime <file>` names one for a single command, and `INTERPRETER_RUNTIME` names one for every project that declares none.

```json
{ "runtime": "./lox.wasm" }
```

A command with no runtime to run fails before it reads a program, and `interpreter build` packs the runtime into the bundle so it runs anywhere.

### wasm or native

A runtime runs as a `.wasm` unless the project says otherwise. A `.wasm` runtime runs in a sandbox, where a program reaches the outside only through the host modules its grants allow. It is the same module the JS host loads, so a program gives the same output in a page and in a terminal.

A native runtime is the same crate built as a `.so`, `.dylib` or `.dll`, as `make native` builds Lox's to `target/native/`. It runs faster, with no sandbox, so the grants of `interpreter.json` do not hold it and a plugin never loads. Use one only for a runtime you build yourself. It loads from a local path, never a URL, through `"runtime": { "native": "./lox.dylib" }` or `--runtime-native <library>`.

| | `.wasm` | Native |
|---|---|---|
| Sandbox and grants | Held | None |
| Plugins and eval groups | Yes | No |
| Loads from | A path or a pinned URL | A local path |
| Speed | Compiled ahead for the machine | Faster, with no sandbox to cross |

Every command on a native runtime prints one warning to stderr, and so does a bundle that carries one. The runtime runs in a child process, so a panic or a crash in it fails the run with an error and the CLI reports it.

```text
warning: native runtime, it runs outside the sandbox and the grants of interpreter.json do not hold it
```

## Commands

| Command | Does |
|---|---|
| `interpreter run <file>` | Runs a script, a packed `.interpreter`, stdin, or `-c <code>`. `--web` runs it in headless Chrome on the JS host |
| `interpreter build` | Packs the project into `app.interpreter`. `--app` writes a standalone binary, `--web` a `dist/` folder for the browser |
| `interpreter test [path]` | Runs every `*_test.lox` file in a fresh session. A file passes when it ends cleanly |
| `interpreter init [name]` | Creates a project with `main.lox`, `interpreter.json` and an `index.html`. `--bare` leaves out the page |
| `interpreter add <name>=<source>` | Declares an import in `interpreter.json`, by URL or by path |
| `interpreter remove <name>` | Removes an import |
| `interpreter lock` | Downloads every URL import once and pins its digest in `interpreter.lock` |
| `interpreter serve` | A dev server with live reload, on `127.0.0.1:5173` unless `--host` and `--port` say otherwise |
| `interpreter actor <file>` | Runs a pool of actors from an `actor.yml` |
| `interpreter uninstall` | Removes the binary and its PATH entry |

| Flag | Commands | Sets |
|---|---|---|
| `--memory <MB>`, `--ops <n>` | `run`, `test` | The limits of a run |
| `--events <file>` | `run` | One event per line for `receive()` |
| `--preempt <n>`, `--save-state <file>`, `--restore-state <file>` | `run` | Stop every `n` back-edges, and save or resume a run |
| `--manifest <file>` | every command | The manifest in place of `./interpreter.json` |
| `--runtime <file>`, `--runtime-native <library>` | every command | The runtime in place of the one `interpreter.json` names |

## A project

`interpreter init` creates a project on the runtime `--runtime` names, and writes its path into `interpreter.json`.

```text
$ interpreter init hello --runtime lox.wasm
created hello/
$ cd hello
```

`main.lox` imports `stars.lox` by its path.

```lox stars.lox
// a bar of n stars for a chart in the terminal
fun stars(n) {
    var bar = "";
    for (var i = 0; i < n; i = i + 1) bar = bar + "*";
    return bar;
}
```

```lox main.lox
var stars = import("./stars.lox").stars;

print "lox " + stars(3);
print "sdk " + stars(5);
```

```text
$ interpreter run main.lox
lox ***
sdk *****
```

A test is a `*_test.lox` file. It fails when its run ends with an error or a status other than 0, and then `interpreter test` exits with 1.

```lox stars_test.lox
var stars = import("./stars.lox").stars;

fun expect(got, want) {
    if (got != want) {
        print "got '" + got + "' for '" + want + "'";
        exit(1);
    }
}

expect(stars(0), "");
expect(stars(2), "**");
```

```text
$ interpreter test
(successful) stars_test.lox
```

`interpreter build` packs the scripts, the manifest and every import into one `app.interpreter` that runs wherever `interpreter` is installed.

```text
$ interpreter build
packed app.interpreter (4 files)
$ interpreter run app.interpreter
lox ***
sdk *****
```

## Packages by URL

`interpreter add` declares an import under the name the code uses. The source is a path or a URL to a `.lox` module, a `.wasm` plugin or a `.interpreter` package, such as one a GitHub release attaches. This one takes a module from this repo at a fixed commit.

```text
$ interpreter add util=https://raw.githubusercontent.com/dylan-sutton-chavez/interpreter/da9bda4365e8e7f62a7f9449964fef94874c51e5/docs/util.lox
+ util       https://raw.githubusercontent.com/dylan-sutton-chavez/interpreter/da9bda4365e8e7f62a7f9449964fef94874c51e5/docs/util.lox
updated interpreter.json, run interpreter lock to pin it
$ interpreter lock
wrote interpreter.lock
```

```lox main.lox
var util = import("util");

print util.greet();
```

```text
$ interpreter run main.lox
hello from a package
```

`interpreter lock` downloads each URL once and writes its digest to `interpreter.lock`. `run`, `test` and `build` refuse any other bytes. Run it after each change to `interpreter.json` and commit `interpreter.lock` with the code. An import can also pin its bytes in the URL with a `#sha256-<64 hex>` fragment.

A package describes itself in its own `interpreter.json`.

| Field | Rule |
|---|---|
| `name` | Up to 40 lowercase letters, digits and single hyphens, starting with a letter. Never `all`, `main` or `eval` |
| `version` | `major.minor.patch` |
| `description` | One line, up to 60 characters |
| `repository` | An `https` URL |
| `docs` | A folder of `.mdx` pages that `interpreter build` packs with the package |

## Grants

A program reaches the outside only through host modules. The CLI serves two and the JS host serves `net`.

| Module | Calls | Scope of a grant |
|---|---|---|
| `net` | `request(method, url, headers, body, inflate, timeout)` gives an id, then `response(id)`, `read(id)` and `close(id)`. `connect(url)` and `send(id, data)` for WebSockets | `net:<host>`, or `net:<host>/<prefix>` for the paths under it |
| `files` | `open(path, inflate)` gives an id, then `read(id)` and `close(id)` | `files:<file>`, or `files:<dir>/` for every file below it |

The root `interpreter.json` grants them in `permissions`, which maps a holder to entries written `module:scope`.

| Holder | Holds |
|---|---|
| `main` | The project's own code |
| An import name | That package |
| `all` | The project and every package it imports |

A package lists what it needs in its own `interpreter.json` and can only pass on what its importer gave it. A call outside its grant raises before anything leaves the process.

```lox-manifest
{ "permissions": { "main": ["net:api.example.com"] } }
```

```lox
var net = import("net");
net.request("GET", "https://other.example/");
```

```output
'main' has no net:other.example, interpreter.json grants it net:api.example.com
[line 2] in script
```

## A CLI of your own

`interpreter::cli` is a kit, public behind the `cli-*` features of the crate. A `Kit` takes a runtime and the commands you wire, each behind a feature. The `interpreter` binary is `Kit::per_project`, the kit that runs whatever runtime a project names, and a runtime of yours gets a CLI of its own with `Kit::new`. With no arguments this one prints its help.

```rust standalone_crate
use interpreter::cli::cmd::{run, test};
use interpreter::cli::{Kit, Runtime};

// the native runtime meters its memory through this allocator
interpreter::allocator!();

fn main() {
    Kit::new("calc", "0.1.0", Runtime::native(&interpreter_lox::RUNTIME))
        .title("A CLI for calc programs")
        .command(run::Run)
        .command(test::Test)
        .main()
}
```

`Runtime::native` links the runtime into the binary. `Runtime::wasm(bytes, &DESCRIPTOR)` loads its `.wasm` instead, which also lets the binary load plugins. `.module(...)` serves a host module such as `interpreter::cli::net::Net`, and `.field(interpreter::cli::perms::FIELD)` with `.access(Arc::new(interpreter::cli::perms::Perms))` holds each package to its grants. This one needs `interpreter = { version = "1", features = ["cli-run", "cli-test"] }`.

| Feature | Command or part |
|---|---|
| `cli` | Every part below, the set the `interpreter` binary wires |
| `cli-kit` | The `Kit` alone with no command |
| `cli-run`, `cli-test`, `cli-build`, `cli-init`, `cli-serve`, `cli-actors`, `cli-uninstall` | The command of that name |
| `cli-actors-server` | The live server an actor pool becomes |
| `cli-packages` | `add`, `remove` and `lock` |
| `cli-net`, `cli-files` | The host modules for requests and sockets, and for local files |
| `cli-perms` | Grants |
| `cli-docs` | The pages a package ships, held to the docs convention |
| `cli-web` | `--web` runs on headless Chrome |
| `cli-wasm` | Runtimes and plugins as `.wasm` |
| `cli-native` | Runtimes as native libraries |
| `cli-coverage` | The lines each native run executed |
