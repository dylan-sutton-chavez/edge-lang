# Command line interface

The `edge` CLI runs programs on mini, the reference runtime, on macOS, Linux and WSL. It embeds `edge.wasm`, the engine and mini built from the same source the JS host loads, precompiled for the machine.

`edge` is the composition of the [CLI kit](../02-sdk/16-cli.mdx) that wires every command below. A runtime of your own gets a CLI from the same kit, as [Your runtime and its CLI](../01-get-started/03-use-cases/01-your-runtime.mdx) shows.

The CLI serves [net](../04-reference/04-system.mdx#net) in Rust and the browser serves it in TypeScript, and one suite of cases holds both to the same answers. A program answers the same on both hosts.

```bash
edge run main.mini                     # run a script or a .edge or stdin (--web)
edge build                             # pack a portable .edge (--app or --web)
edge actor actor.yml                   # run a pool of cooperative actors
edge serve                             # dev server with live reload
edge test                              # run *_test.mini files
edge init my-app                       # scaffold a project
edge publish app.edge                  # send a packed .edge to a registry
edge add slugify=./slugify_mod.wasm    # add a module to edge.json
edge remove slugify                    # remove a module from edge.json
edge lock                              # resolve edge.json into edge.lock
edge uninstall                         # remove the binary and the PATH entry
```

## Install

The CLI builds from a clone of [the repo on GitHub](https://github.com/dylan-sutton-chavez/edge-lang).

```bash
git clone https://github.com/dylan-sutton-chavez/edge-lang
cd edge-lang
make wasm-cli js lucide
cargo install --path cli
```

- `rust-toolchain.toml` pins the Rust toolchain and its wasm target, and rustup fetches both on the first build.
- `make js` and `make lucide` run Deno, and `make lucide` fetches the icon names Lucide publishes over the network.
- `cargo install` embeds what `make wasm-cli js lucide` built and fetches nothing. It puts `edge` in `~/.cargo/bin`.
- `EDGE_WASM` points the build at another `edge.wasm`.
- To upgrade, run `git pull` and the last two lines again.
- The full setup is in `CONTRIBUTING.md` at the root of the repo.

A tagged release on [GitHub Releases](https://github.com/dylan-sutton-chavez/edge-lang/releases) also attaches `cdn.tar.gz`, the tree of that release's builds. Its `cli/` folder holds a prebuilt `edge-<target>.tar.gz` for macOS and Linux, and the Linux binaries are static.

## A project

A project is a folder with an `edge.json` at its root, and every command below works on one. This one turns the titles of posts into URL slugs with Edge Lang's example plugin.

### Create it

Run `edge init` with the name of the project.

```text
$ edge init slugs
  created slugs/
    ├─ index.html
    ├─ main.mini
    └─ edge.json

  cd slugs && edge serve
```

| File | What it holds |
|---|---|
| `main.mini` | The entry point, a script that prints one line |
| `edge.json` | The manifest of the project |
| `index.html` | A page that runs `main.mini` in the browser |

The manifest starts with one field.

```json
{
  "edge": "0.9.7"
}
```

The `edge` field is the lowest engine the project runs on, the version of the CLI that made it, and an older CLI refuses to run the project. Nothing else resolves until you declare it. [edge.json](../04-reference/03-modules.mdx#edgejson) describes every field.

### Add a plugin

A plugin is a `.wasm` module an import names by path or by URL. `make plugin` builds the plugin crate's example as `slugify_mod.wasm` under `target/wasm32-unknown-unknown/release`. Copy it into the project and declare it.

```text
$ edge add slugify=./slugify_mod.wasm
  + slugify    ./slugify_mod.wasm

  updated edge.json
```

```json
{
  "edge": "0.9.7",
  "imports": {
    "slugify": "./slugify_mod.wasm"
  }
}
```

A URL works the same way, as `edge add slugify=<url>`, and `edge lock` then pins the digest of the bytes it serves. [Plugins](../02-sdk/15-plugins.mdx) covers writing one.

### Split it into modules

The code goes in two files. `slug.mini` wraps the plugin's `Slugger`, which lowercases a title and joins its words with dashes.

```text
import slugify

fn slug(title):
    s = slugify.Slugger()
    s.add(title)
    return s.build()
```

`main.mini` imports it with a relative import, which reads `slug.mini` beside it.

```text
from .slug import slug

for title in ["Edge in five minutes", "Your runtime, and its CLI!"]:
    print(slug(title))
```

```text
$ edge run main.mini
edge-in-five-minutes
your-runtime-and-its-cli
```

A test can import the same function without running the script. [Modules](../04-reference/03-modules.mdx) lists every form an import takes.

### Lock it

`edge lock` writes `edge.lock` beside the manifest. It records the URL and the digest of each version `edge.json` declares and of each bare URL, and a path carries its own bytes. `edge run`, `edge test` and `edge build` read the lock and never ask the registry themselves.

```text
$ edge lock

  wrote edge.lock
```

> [!IMPORTANT]
> Run `edge lock` again after every change to `edge.json`, and commit `edge.lock` with the code. A version the lock does not hold stops the run with `'<name>' is not locked in edge.lock`, and the CLI adds `help: run edge lock` below it.

### Test it

`edge test` finds every `*_test.mini` file of the project and runs each one in a fresh session. A file passes when it ends cleanly or exits with 0, so a failed `assert` fails it. `slug_test.mini` checks two titles worked out by hand.

```text
from .slug import slug

assert slug("Edge in five minutes") == "edge-in-five-minutes"
assert slug("  Spaces, commas & marks  ") == "spaces-commas-marks"
```

```text
$ edge test
  (successful) slug_test.mini

  1/1 files passed · 0.0s
```

A check the code does not meet fails the whole file and prints where. The plugin keeps accents, so a title with them fails this one.

```text
$ edge test
error: AssertionError
  --> ./slug_test.mini:4:1
  |
4 | assert slug("Ünïcode titles") == "unicode-titles"
  | ^

  (unsuccessful) slug_test.mini

  0/1 files passed · 0.0s
```

The command exits with 0 when every file passes and 1 when one fails. [edge test](#edge-test) covers the other exit codes and `--web`.

### Build it

`edge build` packs the project and everything it imports into one artifact.

```text
$ edge build

  packed app.edge (6 files)
  70.86 KB

  run  edge run app.edge   or send it to an actor eval group
```

`app.edge` holds the three scripts, the manifest, the lock and the plugin, and it runs on any machine with `edge` installed. `edge build --app` writes a standalone binary instead, and `edge build --web` a folder any browser runs.

A package also carries a name, a version and a one line description in its `edge.json`, which [Package fields](../04-reference/07-registry.mdx#package-fields) lists.

## edge run

Runs a script and streams its output to the terminal. An uncaught error prints a traceback to stderr and exits 1.

```text
$ edge run broken.mini
before
error: ZeroDivisionError: division by zero
  --> broken.mini:2:1
  |
2 | x = 1 / 0
  | ^
```

| Input | Example | Notes |
|---|---|---|
| A file | `edge run main.mini` | Piped stdin feeds `input()` one line per call |
| Inline code | `edge run -c 'print(1)'` | Piped stdin feeds `input()` the same way |
| Piped stdin | `cat main.mini` piped into `edge run` | Stdin is the script, and a terminal on stdin is an error |
| A packed artifact | `edge run app.edge` | A `.edge` or an app binary runs exactly as `./app` would |

`exit(code)` ends the run cleanly with that code and no traceback, and `exit()` ends it with 0. A code that is not an int raises a `TypeError` and exits 1.

A run reads piped stdin while the runtime loads, so a pipe a writer holds open with nothing in it leaves the run with no input instead of holding it. A writer that pipes anything at all is waited for until it closes.

### Named outputs

`send(channel, line)` writes one line to a named output, and outside an [actor pool](./03-actors.mdx) the host serves those names itself, in order with what the run prints. A name prints its lines under its own name, and a name that starts with `file:` writes the rest of the name as a file in the directory the run started in, made fresh at its first line. A name holding `..` or an absolute path is refused before anything is written. Only the root package writes a file channel without a grant, and another package writes only below its own directory, where its `files` grant reaches. An eval run in a pool cannot send at all.

```text
$ tiny run github-hour.flow.yaml
top_stars
{"repo":{"name":"Niko1221/Strata"},"count":4}
busy_branches
{"repo":{"name":"TheCak3/Learning-plan-Math-KSU"},"branch":"main","count":15}
```

That run is `tiny`, the CLI of [Tiny](../01-get-started/03-use-cases/03-tiny.mdx), which composes the same `run` command, so named outputs read alike under both binaries. Its flow also names `activity.csv`, which lands in the directory the run started in.

### Run flags

| Flag | Effect |
|---|---|
| `--events <f>` | Each line of the file or FIFO feeds one `receive()`. End of input parks the script. |
| `--save-state <f>` | On a wait the engine cannot serve, write a [snapshot](../02-sdk/11-snapshots.mdx) to the file and exit 0. |
| `--restore-state <f>` | Boot from a snapshot instead of a script and keep running. An unreadable file exits 2. |
| `--preempt <n>` | Yield every `n` loop back-edges and resume. A program with no suspension point stays snapshottable. |
| `--memory <MB>` | Memory the run may hold, 256 by default. See [Limits](../02-sdk/12-limits.mdx#sandboxed-execution). |
| `--ops <n>` | Operations the run may spend, 100 million by default. |
| `--web` | Run on the browser host in headless Chrome instead of the native engine. |

- Without `--save-state`, a script parked on a wait the engine cannot serve prints an error and exits 1.
- `edge test` takes `--memory` and `--ops` too.

### Run on the browser host

`--web` runs the script on the browser host in headless Chrome. The JS host and the engine come out of the binary and are served on a loopback port. Only the modules the manifest declares by URL leave the machine.

- It drives a Chrome the system already has.
- Without one, it offers to download one the first time into `~/.local/share/edge/chromium`. `edge uninstall` offers to remove it.
- `EDGE_CHROME_PATH` names a browser directly.
- `--events`, `--save-state`, `--restore-state` and `--preempt` belong to the native engine. They are refused beside `--web` rather than ignored.
- `--memory` and `--ops` apply on both hosts.

### Module resolution

Every run happens under the [sandbox limits](../02-sdk/12-limits.mdx).

- A bare import resolves through [`edge.json`](../04-reference/03-modules.mdx#edgejson). Declare it with `edge add` and resolve it with `edge lock` first.
- A declared version resolves through the [`edge.lock`](../04-reference/03-modules.mdx#edgelock) beside the manifest that declared it.
- A relative import loads from disk relative to the importing file.
- A dotted import loads from the nearest `edge.json` directory.

### Cache

| What | Where | Rule |
|---|---|---|
| Downloaded modules | `~/.cache/edge/modules` | Each URL downloads once, 64 MB at most |
| Module pins | a `.lock` sidecar beside each download | Holds its SHA-256. A later run refuses on drift until you remove the entry. |
| Absent remote manifests | a `.missing` marker | A remote `edge.json` that answered 404 is skipped on later runs |
| Compiled plugins | `~/.cache/edge/plugins` | Cranelift machine code keyed by the hash of the `.wasm`, compiled on first use. An entry no run has mapped for 30 days leaves at the next compile |

`$XDG_CACHE_HOME` replaces `~/.cache` when it is set.

### Module errors

Each module below fails at compile time, at the import that names it. ` (via <importer>)` is appended when another module reached it. The JS host fails every row but the eval group the same way.

| Module | Message |
|---|---|
| A `.so` or `.dylib` | `module 'fastmath' is not supported, ship a .wasm` |
| A `.wasm` that does not load | `module 'fastmath' is not a valid plugin, <reason>` |
| A `.js` or `.mjs` | `module 'charts' is JavaScript, ship a .mini or a .wasm` |
| A plugin, or a URL off the composition's origin, in an [eval group](./03-actors.mdx#untrusted-code) | `module 'fastmath' is not available to untrusted eval runs` |

## edge serve

Serves the current directory for browser apps. It reloads the page on any file change through a small polling client injected into served HTML.

```text
$ edge serve
  http://localhost:5173
  watching .
```

| Flag | Default | Effect |
|---|---|---|
| `--port <n>` | `5173` | Port to listen on |
| `--host <addr>` | `127.0.0.1` | Bind address. With `0.0.0.0` the banner adds your LAN URL for a phone on the same network. |
| `--open` | off | Open the app in a browser once the server is up |

On a loopback address it answers only a request whose `Host` names that address, and any other gets 421, so a page on another site cannot read the project through a name rebound to `127.0.0.1`. A path through a dot entry such as `.git` or `.env`, or through a link that leads out of the directory, answers 404.

## edge test

Discovers `*_test.mini` files recursively and runs each in a fresh session. It skips `dist/` and hidden directories and prints a verdict per file. A directory argument narrows discovery to that subtree, and a file argument runs that file alone.

```text
$ edge test
  (successful) main_test.mini
  (successful) lib/parse_test.mini

  2/2 files passed · 0.0s
```

- The verdict comes from how the file ends, never from parsed output. A file passes when it ends cleanly or exits with 0, and what it prints shows above its verdict.
- An uncaught error fails the file and prints its traceback to stderr.
- State never leaks between files.

| Exit code | Meaning |
|---|---|
| `0` | Every file passed |
| `1` | A file failed, or no `*_test.mini` was found |
| `2` | The engine session could not start |

`--web` runs the same files on the browser host in headless Chrome. A package proves it works where its host calls run in a real browser. One browser serves the whole suite with a fresh page per file.

- Discovery and the exit codes stay the same.
- The engine comes out of the binary the way [`edge run --web`](#run-on-the-browser-host) gets it.

## edge init

Creates a ready-to-serve project. With no argument it scaffolds the current directory.

```text
$ edge init my-app
  created my-app/
    ├─ index.html
    ├─ main.mini
    └─ edge.json

  cd my-app && edge serve
```

- `--bare` skips `index.html` for script-only projects, and its last line then names `edge run main.mini` in place of `edge serve`.
- The manifest holds only the `edge` version that scaffolded it. Nothing resolves until `edge add` fills it.
- A directory it is given must not exist yet, even empty. With no argument it writes into the current directory and never overwrites a file. When one of the files it would write already exists it names that file and writes none of them.

## edge add and edge remove

Edits [`edge.json`](../04-reference/03-modules.mdx#edgejson) by name, so a registry package never needs its URL pasted. Each line prints the name and what it wrote.

```text
$ edge add slugify=./slugify_mod.wasm
  + slugify    ./slugify_mod.wasm

  updated edge.json
```

| Form | Writes |
|---|---|
| `edge add <name>` | The newest version of that package in the registry the composition names |
| `edge add <name>@0.1.0` | That version |
| `edge add <name>=<url>` | That URL or path |

- An unknown name or version aborts the whole command before any write.
- A URL goes to `imports` too. Each host tells a code module from a native module by the artifact.
- A `.js` or `.mjs` URL is refused before anything is written.
- `edge add` lists what each new package asks to be granted, and its last line names what comes next, the grants and then `edge lock`.
- `edge add` keeps `extends` and every other key already in the manifest.
- `edge remove` deletes entries by name the same way.
- Neither command touches `edge.lock`.

## edge lock

Turns each version `edge.json` declares into the URL and digest of that release.

It writes them to [`edge.lock`](../04-reference/03-modules.mdx#edgelock) beside the manifest, with a line per package it resolved. Commit the lock. Every other command reads it.

- This is the only command that asks a registry where a name points.
- It rebuilds the whole lock each time. Run it again after editing `edge.json` to bring the two back in step.
- It records a digest for a bare URL too. Those bytes are pinned as well.
- `edge run`, `edge test` and `edge build` read the lock and never resolve a version themselves.

## edge build

Packs the project and its imports into one artifact.

| Command | Writes | Carries | Runs on |
|---|---|---|---|
| `edge build` | `app.edge` | The project, its declared modules, each lock, the readme, the license and the docs | A host that has `edge`, or an actor eval group |
| `edge build --app` | `app`, a standalone binary | The same, appended to this `edge` binary, without the docs | Any host of the same OS and CPU, offline, with nothing installed |
| `edge build --web` | `dist/` | The JS host under `dist/js/`, `edge.wasm`, every declared module and a rewritten `edge.json` | Any browser, offline |

`--out <path>` replaces the default output, `app.edge`, `app` or `dist/` per mode.

> [!WARNING]
> A build refuses to pack while a declared version is unlocked. Run `edge lock` after every change to `edge.json`.

- Every mode carries each module the manifest declares by URL, with the files it imports beside it. The artifact is the whole program.
- A `.edge` and an app binary carry the lock beside each manifest they carry. The artifact resolves its own names.
- A `--web` build rewrites every root import to a vendored path, its relative imports and a sibling `edge.json` included. It leaves the root lock out of `dist/`, and a nested package keeps its own.
- An app binary honors the run flags `--save-state`, `--restore-state`, `--preempt` and `--events`.
- A `.edge` and an app binary carry the `README.md` and any `LICENSE` at the project root.
- A `.edge` carries the pages when `edge.json` declares a `docs` directory. They sit under a reserved `@docs/` prefix no import can reach.

Pages must follow the [package docs](../04-reference/07-registry.mdx#package-docs) convention, or the build fails.

## edge publish

Uploads a `.edge` packed by `edge build` to the registry the composition names with `registry(r)` in the [CLI kit](../02-sdk/16-cli.mdx). Set `EDGE_TOKEN` first to a token that registry issued.

> [!COPY] edge publish app.edge

- The artifact is the whole request. The name and version come from the manifest inside it.
- The CLI signs each publish with the token rather than sending it. The token never leaves your machine.
- A bundle that carries a `.js` or `.mjs` file is refused before it is sent.
- Publishing a version that already exists exits 2 instead of 1. A script can tell it apart from a failure.

What the registry reads, the naming rules and the signing are in [Publishing](../04-reference/07-registry.mdx#publishing).

## edge actor

Runs many programs as cooperative actors over a few threads, described by an `actor.yml`. The manifest, the groups, the server and untrusted code are in [Actors](./03-actors.mdx).

> [!COPY] edge actor actor.yml

## edge uninstall

Removes the `edge` binary from the folder it runs from, its cache and any `PATH` entry for that folder in your `~/.bashrc` or `~/.zshrc`.

## Global flags

| Flag | Effect |
|---|---|
| `--manifest <file>` | Use a specific manifest instead of `./edge.json` |
| `--version`, `-v` | Print the version |
| `--help`, `-h` | Print the command list |

`Ctrl+C` cancels a running command with exit code 130.
