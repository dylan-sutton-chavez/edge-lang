# Compiler

The compiler has two stages and no AST. The lexer turns the source into tokens through the token table a runtime brings, and a single-pass Pratt parser turns the tokens straight into bytecode in an `SSAChunk`. The parser routes on token kinds and never on how a table spelled them, so every table compiles a program to the same bytecode.

- The lexer walks the source as raw bytes in linear time.
- Lex-time diagnostics collect in a `Vec<LexError>` returned beside the token stream.
- `edge.wasm` and the module loader push them into the diagnostics of the parser, so one report holds both.
- Each construct is parsed and lowered in one traversal, with SSA versioning and phi nodes at control-flow joins.

This page covers token-level and bytecode-level mechanics. The grammar and the forms of literals, strings and f-strings live in [Parser kit](/docs/edge-lang/sdk/parser-kit). [Design](/docs/edge-lang/internals/design) covers the parts that span the pipeline.

## Tokens

The lexer produces `Token` values of a kind, a line and two byte offsets, never copies of the text, plus two flags the parser reads, as [Offset tokens](#offset-tokens) shows. A kind names a token and not its text, so `BlockClose` is `end` in uptime and `}` in a braces table, and `Not` is `!` in mini and `not` in uptime.

| Category | Kinds |
|---|---|
| Keywords | `False`, `Nil`, `True`, `And`, `As`, `Assert`, `Async`, `Await`, `Break`, `Class`, `Continue`, `Fn`, `Delete`, `ElseIf`, `Else`, `Catch`, `Finally`, `For`, `From`, `Global`, `If`, `Import`, `In`, `Is`, `FnExpr`, `Outer`, `Not`, `Or`, `Empty`, `Throw`, `Return`, `Try`, `While`, `With`, `Yield` |
| Soft keywords | `Match`, `Case`, `Type` |
| Wildcard | `Underscore`, a lone `_` |
| Operators | 1, 2 and 3 character forms such as `Plus`, `EqualEqual`, `PowEqual` and `FloorDivEqual` |
| Comparisons | `IsNot` and `NotIn`, for a table that spells either as one word or symbol |
| Delimiters | `ParenOpen`, `ParenClose`, `BracketOpen`, `BracketClose`, `BraceOpen`, `BraceClose`, `Colon`, `Comma`, `Semi`, `Dot` |
| Literals | `Name`, `Int`, `Float`, `String`, `Bytes` |
| F-string segments | `FormatStart`, `FormatText`, `FormatEnd` |
| Structure | `Comment`, `Newline`, `Indent`, `Dedent`, `LineBreak`, `Eof`, `BlockOpen`, `BlockClose` |
| Kit pieces | `Let`, `Arm`, `Range`, `RangeInclusive` and `Question`, which a table spells only when its `shapes` turn on a binding word, match arms, ranges or a `?` conditional |

A leading UTF-8 BOM (`EF BB BF`) is skipped before scanning. Without that the marker would fuse with the first identifier.

### Token tables

A table is a `Syntax`. A runtime hands it to the lexer and the parser as a type that implements `Spelling`, as `lex_as::<S>` and `Parser::<_, S>::spelled` take it, so the table compiles in as constants. It holds the reserved words with their tokens, the symbols with theirs, an operator table built from the symbols, how a block opens and closes, the comment marker, and whether the definition word is soft.

A table turns on only the scans it needs. Each switch is a constant of the table, so a table that needs none pays for none.

- `Blocks::Braces` turns on the block scan of [Braces](#braces) in place of indentation, and `Blocks::Words` the scan of [Block words](#block-words).
- A reserved word of two words, such as `else if`, turns on the phrase scan.
- A symbol whose second byte is neither its first nor `=`, such as `~/`, turns on the pair scan.
- A `!` that spells `not` turns on the check that tells a negation from an f-string conversion.
- A comment marker other than `#`, such as `//`, is matched before any symbol it would start.

### Soft keywords

`match`, `case` and `type` collide with ordinary names, and so does a soft definition word such as mini's `fn`. The scanner fills one token buffer, sized from the source length, and a pass over that buffer then decides what each one is in place. The pass walks the buffer once with a level for each open bracket, so it marks soft words, comprehension elements and assignment heads in time linear in the tokens however often a statement repeats them.

- `match` and `case` stay keywords only when they start a statement and its header opens a block, at a colon in mini and indent or a `{` in a braces table. That opener must sit outside brackets and before any `=`, newline or `;`.
- `type` stays a keyword only when it starts a statement and a name follows, as in a type alias, which the parser refuses with `type aliases are not supported`.
- A soft definition word stays a keyword only when it starts a statement, or follows `async`, and a name follows it.
- Everywhere else the word becomes a `Name`.

`match x:` and `match (a, b):` keep keyword force. A call like `match(a, b)` and a binding like `type = nil` stay ordinary code.

```edge
fn match(s, p):
    return s

type = nil
print(match(1, 2))
print(type)
```

```output
1
None
```

`_` always emits as `Underscore`. The parser tells a wildcard from a name by grammar.

### Numbers and strings

`Int` and `Float` are the only numeric token kinds. A table that refuses suffixes, as mini and uptime do, reports `invalid suffix on numeric literal` for a letter right after a number, as in `1j`.

- A misplaced or doubled `_` raises `invalid '_' in numeric literal` or `consecutive '_' in numeric literal`. One `_` may follow a radix prefix, as in `0x_FF`.
- An empty radix body such as `0x` raises `missing digits in numeric literal`.
- A trailing dot such as `5.` is valid.
- An empty exponent such as `1e` is left to the float parser. That avoids false positives inside format specs.

The identifier scanner recognises a string prefix right before the opening quote. `prefix` looks it up in the table for the literal it opens, an f-string, a string or bytes, and a `b` prefix yields a separate `Bytes` token.

Backslash escapes are consumed at lex time and decoded by the parser. `\N{NAME}` is not implemented, because the Unicode name database would add about 200 KB to the WASM artifact.

String errors anchor on the opening quote. The caret points at the literal and not at the end of the line. The messages are `unterminated string literal`, `unterminated triple-quoted string literal` and `unterminated f-string literal`.

### Comments

The marker of the table, `//` in mini and `#` in uptime, runs to the end of the line. Comments are emitted as `Comment` tokens, not discarded.

Tools can round-trip the source. The parser skips `Comment` and `LineBreak` when it peeks.

## Dispatch tables

Compile-time tables drive the scanner. `BYTE_CLASS` in `syntax/lexer/tables.rs` serves every table, and `operators` in `syntax/lexer/syntax.rs` builds the operator table of each `Syntax` from its symbols.

```rust
// a 256 entry table replacing per-byte branches with indexed flag loads
pub static BYTE_CLASS: [u8; 256] = { /* ... */ };

// the byte table of a symbol list leaving `}` to the scanner
pub const fn operators(symbols: &[(&str, TokenType)]) -> [[TokenType; 4]; 128] { /* ... */ }
```

- Identifiers, digits and whitespace use a `scan_while(pred)` driver that loops over `BYTE_CLASS[b] & FLAG`.
- An operator takes one indexed load of the operator table by its first byte. The next byte then picks the doubled form, such as `**`, or the `=` form, such as `*=`, and a third byte picks `**=`.
- A symbol whose second byte is neither its first nor `=`, such as mini's `~/`, has no slot there. The pair scan matches it whole, the longest first.
- `}` has no slot either. The scanner tells the end of an f-string field, of a block and of a display apart itself.
- Keyword lookup goes through the table's `keywords`, the index `index(words)` builds at compile time by length and first byte, which compares a word up to eight bytes long as one packed integer.

ASCII bytes with no operator slot, such as `$`, `?` and `` ` ``, raise `unexpected character` and are skipped.

## F-string tokens

An f-string becomes a sequence of tokens, not a single `String` token. The parser consumes the sequence directly.

```text
f'a {x} b {y + 1}!'

FormatStart
FormatText("a ")
BraceOpen
Name(x)
BraceClose
FormatText(" b ")
BraceOpen
Name(y) Plus Int(1)
BraceClose
FormatText("!")
FormatEnd
```

- The tokens between `{` and `}` come from the main lexer. An interpolation gets the full expression grammar.
- `{{` and `}}` emit no `BraceOpen` or `BraceClose`. They stay in the `FormatText` text and the parser unescapes them.
- Triple-quoted f-strings follow the same structure, with newlines inside the middle segments.
- Nested f-strings live on a stack of open `fields`. Each `}` resumes the right outer template.
- At the end of the source inside an open f-string, the lexer reports `unterminated f-string literal` and synthesises a closing `FormatEnd`. The parser still sees a balanced sequence.

## Blocks

A table opens and closes a block one of three ways, and the parser reads each as the same block.

### Indentation

The scanner keeps a stack of column counts and emits structural tokens at line boundaries.

| Situation | Tokens emitted |
|---|---|
| Blank line or comment-only line | `LineBreak` |
| Inside `(...)`, `[...]`, `{...}` | `LineBreak`, with no `Indent` or `Dedent` |
| Indentation increased | `Newline`, then `Indent` |
| Indentation decreased | `Newline`, then a `Dedent` per level |
| Indentation unchanged | `Newline` |
| Dedent matches no outer level | The diagnostic `unindent does not match any outer indentation level` |
| Mixed tabs and spaces in an indent | `Newline`, then `Eof` to halt the lexer, plus a diagnostic |
| An indent past 100 levels | `Newline`, then `Eof`, plus a diagnostic |

A `nesting` counter goes up on `(`, `[` and `{` and down on `)`, `]` and `}`. While it is above zero, line breaks emit `LineBreak` and the indent stack is frozen. Multi-line expressions inside brackets produce no stray `Indent` or `Dedent`.

At the end of the source the lexer pops every open level as a `Dedent`, then emits `Eof`. A backslash continuation joins two physical lines.

### Braces

A braces table counts no indentation. A line break outside brackets emits `Newline`, and one before a blank or comment-only line emits `LineBreak`.

- A `{` outside brackets and f-strings emits `BlockOpen` after the last token of a header, a name, a literal or a closing bracket. It does the same after a block word, `try`, `except`, `finally` or a statement `else`, and after a trailing comma of a header when the `{` ends the line. Anywhere else it is a `BraceOpen` that opens a display.
- The `}` of a block emits `BlockClose` and closes every bracket its body left open.
- A block nested past 100 levels emits `Eof`, plus a diagnostic.

### Block words

A table of `Blocks::Words` spells `BlockOpen` and `BlockClose` as words, `do` and `end` in uptime, and counts no indentation. With `implicit` on, a header still open at its line end opens its block there, so `for x in xs` needs no `do`, and one `end` closes the statement with every clause it holds. A `do` opens a block on the header's own line, as in `for x in [1, 2] do print(x) end`.

## Offset tokens

A `Token` carries a kind tag, a line, two byte offsets and two flags the pass over the token buffer sets.

```rust
pub struct Token {
    pub kind: TokenType,
    pub line: usize,
    pub start: usize,
    pub end: usize,
    pub comp: bool,  // starts the element of a comprehension
    pub assigns: u8, // counts the `=` ending the targets of its statement
}
```

The parser slices `&source[t.start..t.end]` lazily for names, string content and numeric literals.

- The lexer never allocates a `String` per identifier.
- `lexeme(&t)` is a zero-copy `&str` that lives as long as the source buffer.
- Diagnostics get exact byte offsets for free. The error column is a single `rfind('\n')`.

## Bytecode model

Each instruction is a 4-byte record. It holds a 1-byte `OpCode` (`#[repr(u8)]`) of the table [Opcodes](/docs/edge-lang/sdk/opcodes) covers, a 2-byte operand, and 1 byte of padding.

```rust
pub struct Instruction {
    pub opcode: OpCode, // 1 byte (#[repr(u8)])
    pub operand: u16,   // 2 bytes
}
```

The operand meaning depends on the opcode, as the table's `operand` column states for each.

| OpCode | Operand |
|---|---|
| `LoadConst` | Constant pool index |
| `LoadName`, `StoreName` | Name slot index |
| `Add`, `Sub`, ... | Flags, `INPLACE` for the `op=` form that may update its left side in place, while the inline cache keys on the ip |
| `Call` | `(num_kw << 8) \| num_pos` |
| `BuildList`, `BuildTuple`, `BuildSet` | Element count |
| `BuildDict` | Key and value pair count |
| `BuildSlice` | Part count, 2 or 3, for a slice a key keeps or a store takes, which the register lowering hands to `StoreCut` with no slice built, though an augmented store such as `x[a:b] += v` still builds one to read and store it |
| `Cut`, `DelCut` | The object and its bounds, 3 or 4, which a read or a delete of a lone slice takes with no slice built unless the object is a map, which keys by the slice the bounds make |
| `Jump`, `JumpIfFalse` | Target instruction index |
| `ForIter` | Jump target when the iterator is exhausted |
| `Phi` | Target slot, with the sources in `chunk.phi_sources` |
| `UnpackSequence` | Element count |
| `UnpackEx` | `(before << 8) \| after` |
| `MakeFunction` | Function index in `chunk.functions` |

Operands, the constant pool, the name table and the instruction stream of each chunk are capped at `u16::MAX` (65,535).

## Pratt parsing and precedence

`expr_bp(min_bp)` runs the Pratt loop. Each operator declares a left and a right binding power. The loop pulls in everything bound at least as tightly as `min_bp`.

`parse_atom` advances one token and routes by kind.

```text
Name / Underscore        -> name() (handles walrus, calls)
String / FormatStart     -> string_group() (adjacent str and f-string literals concatenate)
Bytes                    -> one constant, adjacent bytes literals joined
Int / Float              -> emit numeric constant
True/False/Nil/Ellipsis  -> emit dedicated load opcode
BraceOpen                -> brace_literal() (dict, set, comprehension)
BracketOpen              -> list_literal() (list, comprehension)
ParenOpen                -> paren_atom() (grouped expr, tuple, generator, or empty tuple)
Yield                    -> emit_yield() (yield as a value)
FnExpr                   -> parse_lambda()
```

A `BlockOpen` or `BlockClose` where an operand belongs reports `expected expression` and stays for the block it bounds. A closer does the same for the bracket or field it closes, so an empty `{}` field reports only the expression it lacks.

After an atom, `postfix_tail()` handles subscripts, attributes and calls until none apply. It also ends a chain in its store, the `xs[0].v` of an assignment target or a statement such as `xs[0][1] += 1`. `fns[0](-3)`, `obj.method()`, `(lambda x: x)(3)` and `compose(f, g)(x)` all parse the same way.

`*args` and `**kwargs` are accepted in call position.

- Starred unpacking in list, set and dict displays lowers through `ListExtend`, `SetUpdate` and `DictUpdate`.
- A tuple display such as `(1, *xs, 2)` or `x = *a, b` builds a list the same way, then a tuple from it.

Each table's `precedence` gives every operator its left and right binding power by token kind, whatever the table spells it with, and a left power of zero marks a prefix. The parser reads the powers of the table it parses with. A higher number binds tighter, and the levels below are mini's, while uptime's ladder has no bitwise or shift levels.

| Level | Tokens | Notes |
|---|---|---|
| 1/2 | `Or` | Short-circuit |
| 3/4 | `And` | Short-circuit |
| 5 | `Not` as a prefix | Prefix only |
| 7/8 | `EqualEqual` `NotEqual` `Less` `Greater` `LessEqual` `GreaterEqual` `In`, `Not In` or `NotIn`, `Is`, `Is Not` or `IsNot` | Chainable |
| 9/10 | `BitOr` | Bitwise |
| 11/12 | `BitXor` | Bitwise |
| 13/14 | `BitAnd` | Bitwise |
| 15/16 | `LeftShift` `RightShift` | Shifts |
| 17/18 | `Plus` `Minus` | Additive |
| 19/20 | `Star` `Slash` `Percent` `FloorDiv` `At` | Multiplicative |
| 21 | `Minus` `Plus` `Tilde` `Await` as prefixes | Prefix |
| 22/21 | `Pow` | Right-associative |

Only `Pow` is right-associative, since its `r_bp` is below its `l_bp`. An operator never continues past the end of a logical line. `@deco` on the next line stays a decorator.

`infix_bp` handles comparison chains such as `a < b < c`.

1. The parser stores the middle value in a synthetic `#cmp` slot.
2. It emits the first comparison and jumps out on false.
3. It loads the stored value again for the next comparison.

## Lowering

### Short-circuit

`And` and `Or` lower to `JumpIfFalseOrPop` and `JumpIfTrueOrPop`. These peek the top of the stack and pop only when execution continues. Otherwise they jump and leave the value on the stack.

```text
a and b

LoadName a
JumpIfFalseOrPop -> end
LoadName b
end:
```

The result is the operand itself, not a coerced bool, and no extra opcode is needed.

### Conditional expression

`a if cond else b` parses value first, because the value comes first in the text and there is no AST to reorder. On reaching `if`, the parser drains the instructions of the value and emits them again after the condition, shifting their internal jump targets. The condition runs first and only one branch executes.

```text
a if cond else b

LoadName cond
JumpIfFalse -> else
LoadName a
Jump -> end
else:
LoadName b
end:
```

### F-strings

An f-string lowers to its constant chunks and the code of its fields in source order, and closes with `BuildString`, which joins them. How a field turns into text, its [conversion and spec](/docs/edge-lang/sdk/parser-kit#f-strings) included, is up to the runtime.

The `{expr=}` form emits the field text as written, spaces around the `=` included, as a constant after the value and swaps the two, so the field code never moves. Adjacent string literals concatenate at parse time.

## SSA and phi nodes

Each binding emits a fresh slot with a higher version. The parser keeps the current version of each name in a table that allocates the text of a name once, when it first binds, and finds it by hash after that. Names in `chunk.names` are stored as `name_version`.

```edge
x = 1  // x_1
x = 2  // x_2
y = x  // y_1, references x_2
```

```text
chunk.names = ["x_1", "x_2", "y_1"]
chunk.instructions:
  LoadConst 0   (1)
  StoreName 0   (x_1)
  LoadConst 1   (2)
  StoreName 1   (x_2)
  LoadName 1    (x_2)
  StoreName 2   (y_1)
```

A name read before any binding in its chunk targets version 0, such as `x_0`. At run time an unbound `_0` name falls back to the builtins, and a name unbound there too is an error.

Inside a block every store pushes its name and the version it replaced onto a trail. At each control-flow boundary the parser pushes a `JoinNode { start, mid }` of trail positions onto a stack.

```text
enter_block()  -> start = where the trail ends now
mid_block()    -> mid = where the trail ends now, the next branch keeps the current versions
commit_block() -> sort the trail after the split by name, emit Phi for each name stored there
```

A join reads only the names its blocks stored, so its cost follows those stores and not every name in scope. Versions only grow inside a chunk, which is why a branch never restores the versions before it.

Each `Phi` carries the target slot, the version after the join, in its operand. The source slots live in `chunk.phi_sources`, indexed at run time by `chunk.phi_map[ip]`. That keeps `Instruction` at 4 bytes.

```edge
if cond:
    x = 1
else:
    x = 2
y = x
```

```text
LoadName cond_0
JumpIfFalse else_label
LoadConst 0 (1)
StoreName x_1
Jump end_label
else_label:
LoadConst 1 (2)
StoreName x_2
end_label:
Phi x_3 (sources: x_1, x_2)
LoadName x_3
StoreName y_1
```

At run time `Phi` copies the first defined source slot into the target. Exactly one branch ran. Exactly one source is defined.

## Statements

`stmt()` peeks the leading token and routes by kind. Every statement starts with an empty bracket stack, and one that fails without consuming a token skips it, so broken input always ends.

```text
If        -> if_stmt (ElseIf chain, optional Else)
For       -> for_stmt (sync iter, optional Else)
While     -> while_stmt (break/continue patches)
Match     -> match_stmt
Fn        -> func_def_inner
Class     -> class_def_with (bases, body, keywords refused)
With      -> refused, with_stmt parses it for its errors
Try       -> try_stmt (except, else, finally, raise)
Import    -> import_stmt (compile-time resolver lookup)
From      -> parse_from_stmt (named and star imports, same path)
Yield     -> yield expr / yield from
Async     -> async fn, with async for and async with refused
At        -> decorator stack + fn or class
Return    -> expr + ReturnValue
Throw     -> expr + Raise, with raise from refused
Break     -> emits Jump, back-patched to the loop exit
Continue  -> jump to current loop start
Delete / Global / Outer / Empty -> direct emit
Assert    -> Assert opcode (the ", msg" form lowers to a conditional raise carrying msg)
Type      -> refused as a type alias
Name      -> assignment, else name_stmt (augmented, indexed, attribute, call)
Let       -> let_stmt, where the table's binding word leads a store
BlockOpen -> unexpected '{', its block skipped
( [ *     -> assignment, else an expression statement
```

`compile_block` reads a block as its table writes it. In braces and block words that is the statements between `BlockOpen` and `BlockClose`, and in mini and indent those between `Indent` and `Dedent` or on the line of the header. `header_end` eats the colon an indent header ends with and nothing in braces, and a block brace bounds a statement in error recovery the way a line does, so the statement parsers never ask which table they read.

Each statement returns whether it left a value on the stack. The driver emits `PopTop` after expression statements such as `x.method()`. It emits nothing after assignments and control flow.

- The lexer counts on the first token of a statement the `=` that end its targets. An assignment moves the cursor past those targets without compiling them, compiles the value, then comes back to store into each target from left to right, and a `for` or comprehension stores its targets the same way on each item. The value of `d[k()] = v()` runs first, and `a = b = v` duplicates it once per extra target.
- Decorators apply to a definition and a class. The `At` arm peeks for `Class` after the decorator list. Each decorator wraps through `Call,1` between `MakeFunction` or `MakeClass` and the final `StoreName`.
- `raise X from Y` fails with `raise from is not supported`. A bare `raise` raises the current exception again.
- Imports resolve at parse time through a resolver the host injects. No import opcode reaches the VM. See [Modules](/docs/edge-lang/reference/modules).

## Functions

A lambda and a definition both compile their body into a fresh `SSAChunk`.

```rust
self.with_fresh_chunk(|s| {
    s.ssa_versions = outer_versions;
    for p in params { s.bind_param(p); } // each base name at version 0
    s.mark_stmt(); // an error in the body points at its expression
    s.expr(); // a definition compiles its block instead
    s.chunk.emit(OpCode::ReturnValue, 0);
});
```

A free variable is a name that is neither a parameter nor bound locally. It is looked up in the outer chunk.

- `MakeFunction` captures the cells of the enclosing function into `captures`. Each is a `HeapObj::Cell` that its call created.
- Sibling closures over the same variable observe the `nonlocal` writes of each other.
- Capture works at any depth, as in `A -> B -> C` where `C` reads a variable of `A`.

Parameters are stored as names with markers. `*` marks `*args`, `**` marks `**kwargs`, `~` marks a keyword-only parameter, and a trailing `=` marks one with a default. Defaults live in `HeapObj::Func.defaults` and bind to the marked parameters in source order.

Annotations are parsed for their errors and emit no code, on parameters, returns and variables alike. The body chunk keeps how many parameters come before a `/`, which keyword binding refuses to fill, and the line the definition starts on.

## Comprehensions and generators

Every comprehension takes several `for` and `if` clauses and compiles to a function called at once, so its loop variables stay its own. Its first iterable becomes an iterator where the comprehension stands, so an error there points at the comprehension.

- A list, set or dict comprehension builds with `BuildList`, `BuildSet` or `BuildDict` and fills with `ListAppend`, `SetAdd` or `MapAdd`, then returns the result.
- A generator expression is a generator function, its clauses and element running as items are asked for.
- The lexer marks the first token of an element followed by `for` inside brackets. The parser sets those tokens aside, compiles the clauses, then replays the element innermost.
- A walrus in the element binds in the enclosing scope, as a `nonlocal` of the body.

A comprehension that awaits runs as a coroutine the enclosing `async` function awaits. An `async for` clause fails with `async comprehensions are not supported`, and a generator expression that awaits fails with `async generators are not supported`. Starred unpacking inside a comprehension is not supported.

## Limits

The caps are listed in [Source and token limits](/docs/edge-lang/sdk/limits#source-and-token-limits), and their messages in [Diagnostics](/docs/edge-lang/reference/diagnostics#caps). Each stage stops in its own way.

- A lexer cap halts lexing with `Eof`.
- `MAX_EXPR_DEPTH` (200) bounds every recursive descent of the parser through expressions, assignment targets, `del` targets and match patterns. Deep input raises `expression too deeply nested` instead of overflowing the native or WASM stack.
- Blocks nest at most 100 deep by the lexer's cap, and imports at most 64 modules deep, reported as `imports nest deeper than 64 modules`.
- A comparison chain and an `else if` chain each compile in a loop, so their length has no cap.
- Past 65,535 instructions, names or constants, `emit` stops adding and sets `chunk.overflow`. The parser reports the overflow once parsing ends, and the instruction stream never runs.
