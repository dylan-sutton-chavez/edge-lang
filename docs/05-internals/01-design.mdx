# Design

## Overview

The compiler is a single pass with no AST and no IR. Bytecode is the only intermediate representation. Source flows through four stages.

1. A LUT-driven lexer.
2. A Pratt parser that emits SSA-versioned bytecode directly.
3. A peephole optimiser that folds constants.
4. A register interpreter that lowers each chunk once it runs hot.

The shipped `compiler.wasm` is about 250 KB served as brotli, 722 KB raw. It builds for `wasm32-unknown-unknown` with `opt-level = "z"`, `lto`, one codegen unit and `panic = "abort"`, then goes through `wasm-opt`.

- The core is about 27,000 lines of Rust.
- Production dependencies are `hashbrown`, `itoa` and `libm`, plus the in-repo `wasm-abi` crate. SHA-256 is implemented in-tree.
- The WASM build adds `dlmalloc` as the global allocator, behind a pool that reuses freed small blocks. Allocation cost stays flat as live blocks grow.

This page covers the parts that span the pipeline. Tokens, parsing and bytecode emission live in [Compiler](/docs/edge-python/internals/compiler).

## Key mechanisms

- **Register dispatch.** Each chunk lowers to instructions that name frame slots directly. The hot loop is a flat `match` that Rust lowers to a jump table. Opcodes without a register form run as stack opcodes.
- **One register stack.** Every running frame is a window of one stack, from its base to the next frame. A call opens its callee on top, and an error builds the traceback frames only as it unwinds.
- **Inline tag checks and caches.** Register arithmetic and comparisons test the NaN-box tags of both operands inline and take the generic handler for any other type. Attribute loads, stores, method calls and operator dunders cache the field index, method or builtin they last resolved. A call caches the function or the class it opened as a frame. An instance dict carries a shape, an id for its exact keys in order while it only ever gained keys, so a field load or a new attribute checks one number. Any other change to the dict drops its shape, and the sites fall back to checking the name and hash of the entry. A class change or a collection invalidates the caches. Caching is per instruction. Each monomorphic site stabilises on its own.
- **Static scopes.** The names of each function resolve once before anything runs. A name an enclosing function binds becomes a shared `HeapObj::Cell`. The cell is wrapped when that function is called and captured by the definition. Closures observe the `nonlocal` writes of each other. Every other free name reads the binding table of its module by a fixed index. The builtins answer while that binding is unbound.
- **NaN-boxed values.** `Val` is a 64-bit union. It holds 48-bit signed ints inline, IEEE-754 floats, bools, None, an undef sentinel, and 28-bit heap indices. See [Memory model](#memory-model).
- **Mark-and-sweep GC.** Single-colour, with no reference counts. Cycles are reclaimed natively.

## Dispatch shape

The first call of a chunk runs the code the compiler wrote. Its second call, or a loop past 16 back-edges, lowers it to register code that every frame shares. A hot frame carries on from its loop head. A lowered instruction holds an opcode, a flag byte and three 16-bit operands, so one instruction reads two registers and writes a third.

- `LoadAttr` and `Call` sites fuse into `CallMethod` and `CallMethodArgs` when every argument is a single-push load. That holds up to 8 arguments and never across a jump target.
- Local loads become slot operands.
- A compare that feeds a branch becomes one compare-and-jump.
- Lowering runs once per chunk, and every frame of the chunk shares its caches.

A plain call, a method call and a constructor whose `__init__` takes plain parameters open their frame on the frame stack of the running loop without leaving it, and a return hands the loop back to the caller, so Python recursion never recurses in Rust. The call site remembers the function, method or class, so the next call there copies the arguments into the new frame, fills defaults and captured cells, and runs on in the same loop. A plain return pops the frame in that loop too. `CallR` reads a callee and up to five positionals from registers, `CallMethodR` a receiver and up to four, and past the first two the operands sit in an `ArgsR` after the call. The result goes straight to the register that stores it, and a builtin method takes its arguments straight from the registers. A call that a builtin, a dunder or a resumed coroutine makes, or one into code not lowered yet, nests a loop of its own. A frame that suspends becomes a sync frame of its coroutine, which resumes it in place.

Register forms keep int and float math inline. Stack arith and compare opcodes try the same numeric path in `exec_arith_or_compare` before the generic handler.

Constants become values once per chunk. Lowered code reads them from slots after the names.

- Inline-range ints stay inline.
- Wider ints box as `python.bigint` values, see [Wide ints](#wide-ints).
- A decimal literal past 4,300 digits is rejected at parse time.

The instruction format is in [Bytecode model](/docs/edge-python/internals/compiler#bytecode-model).

## Memory model

`Val` is 64 bits and NaN-boxed, with `QNAN = 0x7FFC_0000_0000_0000` and `SIGN = 0x8000...`.

| Tag | Pattern | Notes |
|---|---|---|
| Float | Any non-canonical IEEE-754 | Every NaN is `0x7FF8...`, its sign kept |
| Int | `QNAN \| SIGN \| i48` | 48-bit signed inline, boxed as a FOREIGN value on overflow |
| Undef | `QNAN` | Unbound-local sentinel |
| None | `QNAN \| 1` | |
| True | `QNAN \| 2` | |
| False | `QNAN \| 3` | |
| Heap | `QNAN \| 4 \| (i28 << 4)` | 28-bit index into the heap arena, at most `1 << 28` slots |
| FOREIGN | `QNAN \| 1 << 48 \| gen16 << 32 \| i32` | An entry of the FOREIGN table, its generation and index |

`INT_MAX = 140_737_488_355_327` and `INT_MIN = -140_737_488_355_328`. Inline ints cost one ALU op per arithmetic.

Overflow boxes the result, and a result that fits again comes back inline, so every int has one form and the inner loop never sees a box.

Dicts and sets key by content through `hash_val_with_heap`. Value-equal numbers collapse to one key. `1 == 1.0` and `10**16 == 1e16` hit the same slot.

- Every number hashes by its value modulo the prime 2⁶¹ − 1, so an int, a bool, a float and a wide int that are equal hash alike. An inline int is already below the prime and hashes as itself.
- A NaN hashes its bits.
- `FxBuildHasher` uses a fixed seed. Iteration order is reproducible across runs.

### FOREIGN values

A FOREIGN value is an object the engine holds without knowing its insides, owned by the kind that made it. Its `Val` names an entry of a table in the heap by index and generation, and the entry names the kind, so a freed entry takes the next generation and a stale or forged `Val` finds nothing. A slot whose generation runs out retires instead of being reused.

- A kind registers once by name and gets a token. Only the token reads a payload, everything else passes the `Val` around and calls the operations of the kind.
- Operations a kind lacks are absent, and one that does not apply to an operand answers `NotImplemented`.
- Two kinds of different families are never equal, and the family decides the hash, so `a == b` keeps implying equal hashes. Equality and hashing never run user code.
- The collector marks an entry, then the values its kind traces, and sweeps all entries before dropping any payload.
- A snapshot saves a kind that serializes, and fails with an error naming any kind that does not. A kind either copies across the plugin wire or never crosses it.
- Only slow paths check for a FOREIGN value, so the inline int and float paths pay nothing for it.

### Wide ints

`python.bigint` is the FOREIGN kind of the ints an inline `Val` cannot hold, registered by the Python frontend. A value that fits i128 boxes as an i128 in one allocation, and a wider one as 32-bit limbs.

- Multiplication is schoolbook up to 40 limbs and Karatsuba past that.
- Division is Knuth's Algorithm D. Int to float and true division round correctly, subnormals included.
- Text conversion in a base that is not a power of two refuses more than 4,300 digits, both ways, so a conversion never takes quadratic time on a huge int. Hex, octal and binary have no limit.
- Every operation reserves the memory of its result and checks its work, n^1.585 limbs for a Karatsuba product, against the op budget the VM left on the heap before it starts. A huge `**` or `<<` fails at once instead of running away.

The heap is a `Vec<HeapSlot>` arena. Its free list is capped at 524,288 entries and sorted to prefer low indices.

- Side hashes intern names and string constants up to 128 bytes, one-character strings, bytes up to 128 bytes, and bound methods.
- Equal interned values share one slot.
- Strings built at run time are not interned.

An inline value has no address, so two equal numbers are one value and share one `id`, the boxed word. An `is` built on that would answer differently from CPython, so `is` compares only with `None`, `True`, `False`, `...` and `NotImplemented`. Frames keep their locals in registers rather than in a dict, so there is no `locals()`.

A NaN payload could read as a tagged value, so every NaN is stored as `0x7FF8...` with its sign kept, and two NaNs are one value. A container matches by identity before `==`, so a list holding a NaN contains any other and a set keeps one, as `SameValueZero` does in JavaScript. `n == n` stays `False`.

The allocator counts what each run holds against its memory limit, with a tag on every block naming the run that paid for it, and the runs of one instance share one budget, see [Sandboxed execution](/docs/edge-python/reference/limits-and-errors#sandboxed-execution).

The main `HeapObj` variants are `Str`, `Bytes`, `List`, `Dict`, `Set`, `FrozenSet` (these three keep insertion order), `Tuple`, `Func`, `Range` (with `BigRange` for bounds past i64), `Slice`, `Type`, `ExcInstance`, `BoundMethod`, `NativeFn`, `Class`, `Instance`, `BoundUserMethod`, `Super`, `Property`, `StaticMethod`, `ClassMethod`, `Coroutine`, `Module`, `Iter`, `DictView`, `Cell`, `Code`, and `Extern`. A dict or list made by a class deriving from it stays that variant, and its class and attributes sit in a side table of the heap keyed by its slot, so every builtin handles it as the container it is.

## Garbage collection

Collection triggers when `live >= gc_threshold`, when `alloc_count >= max(live / 4, alloc_limit)`, or when the run holds more than its memory limit. After each sweep the thresholds reset, with `marked` the values the last mark visited.

```text
gc_threshold = max(live * 2, 512, marked / 4)
alloc_limit  = max(marked / 4, 4096)
```

The roots are these.

- The value stack, the with-stack, yields, and the event queue.
- The pending `yield from` value.
- The register stack, which holds every running frame, and slot templates.
- Module binding tables, and cells around class bodies.
- Parked scheduler coroutines and iterator frames.
- Chunk constant pools and inline-cache values.

## Coroutine dispatch

`async def` and a `def` that holds `yield` both compile to `HeapObj::Coroutine`. The primitives a program sees are in [Async](/docs/edge-python/language/async).

A plain `def` inside a coroutine can call a builtin that yields. Its state (`ip`, slots, stack and iterator deltas) is then saved as a `SyncFrame` on the `sync_frames` of the enclosing coroutine, innermost last.

- Resume walks this stack from the inside out before it enters the outer body again. The return value of each helper lands at its original `Call` site.
- An error that escapes a helper raises again at that same site. The handlers of the caller and the traceback notes match a run that never suspended.

`vm.run()` wraps the module body as an implicit coroutine. Top-level statements suspend like `async def` bodies. Dispatch has a single driver, and `top_loop` is the only place that picks coroutines.

`run`, `gather`, `with_timeout`, `await`, and calling a coroutine value all work the same way. They push targets to the scheduler, park the caller in `CoroState::WaitingForChildren`, and yield. The `WaitKind` picks how the wait finishes.

| WaitKind | Finish |
|---|---|
| `Run(target)` | Returns the value of the target |
| `Gather` | Returns the list of results |
| `Timeout` | Enforces a deadline |

When the children finish, the result replaces the saved stack placeholder of the outer coroutine and the outer is marked ready.

A child error, a timeout or a failed host call marks it `CoroState::Raising` instead. The next resume raises the error at the park point. Handlers and the traceback position follow the normal path.

Coroutines carry their own `try` and `except` frames across yields. On entry the stored frames are denormalised onto the live exception stack. A resume moves the saved state onto the live stacks and a yield moves it back, reusing the same buffers.

On a yield they are renormalised and saved. That is how `try: run(coro) except E:` catches the raise of a child across several resume cycles.

## Snapshots

A snapshot holds only the dynamic state of a parked VM. The blob format is in [Blob layout](/docs/edge-python/platforms/rust#blob-layout).

- `save_state` writes `Val` bits verbatim. Heap slots and FOREIGN entries come back at identical indices and generations. References, cycles and interning survive with no remapping.
- A FOREIGN value restores only under a kind registered with the same name and version, and a `Val` naming an entry the blob did not restore fails the restore.
- `restore_state` replays the blob onto a VM booted fresh from the source the blob embeds.
- Chunk-derived tables such as the bytecode, the name pools and the extern table are not stored. They come from the re-parse.

Preemption supplies the parked state when a program never suspends on its own. `set_preempt_interval(n)` makes the dispatch loop sample a counter at loop back-edges. Every `n` hits it takes the ordinary yield path, the coroutine stays ready, and `top_loop` returns `Preempted`.

Sampling is gated on a `frame_safe` flag per frame. The scheduler step sets it, and a call or method call that an instruction makes passes it to its callee, a frame the loop opens included. A call from a builtin or a dunder passes nothing, so native re-entry cannot be preempted by default, and a new re-entrant path inherits that default instead of corrupting a blob.

Restore runs in two passes, because hashing reads the heap.

1. Every slot is materialised. Sets and frozensets land empty.
2. A rehash pass rebuilds the dict indexes and fills the sets. `rebuild_mro` recomputes the linearization of each class.

Inline caches start empty and warm lazily. `Extern` handles resolve by name against the extern table of the re-parsed chunk.

Host-side resources such as in-flight host calls and DOM handles are not part of the snapshot. `state_globals` and `state_stack` inspect a parked run without resuming it. The feature as a program sees it is in [Snapshots](/docs/edge-python/language/snapshots).

A coverage-guided fuzzer drives the lexer, the parser, the VM and this snapshot round trip around the clock, see [Runbook](/docs/edge-python/internals/runbook).

## What the compiler intentionally does not do

- No SSA-wide constant propagation through `LoadName`. The names stay. That keeps the inline cache and fusion paths fast.
- No CSE, GVN, LICM, inlining, branch DCE, or loop folding. The optimiser does constant folding, phi-noop elimination, and dead-instruction compaction with jump-operand remap.
- No JIT. A method JIT needs stencils per architecture, and a tracing JIT duplicates the execution model and complicates the GC.
- No runtime module system. Imports resolve at parse time through a resolver the host injects. See [Modules](/docs/edge-python/reference/modules).
- No complex numbers, `bytearray`, `memoryview`, `Decimal`, or `Fraction`.
- No `asyncio` module. The concurrency primitives are top-level builtins, see [Async](/docs/edge-python/language/async).
