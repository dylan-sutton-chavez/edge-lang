# Runbook

Five checks run beside the test suites. Each one has a `make` target at the root of the repo.

| Check | Command | In CI |
|---|---|---|
| Fuzzing | `make fuzz` | Back to back, about 5 hours a run |
| Miri | `make miri SUITE=vm` | Back to back, one runner per suite |
| Bench | `make bench` | Every push and pull request to `main` |
| Consistency | `make test-cli SUITE=consistency` | Every push and pull request to `main` |
| Std packages | `make test-cli SUITE=std` | Every push and pull request to `main` |

## Fuzzing

The fuzzer feeds mutated source through the lexer, the parser and the VM. It also saves a snapshot at the first park and restores it into a fresh VM. It looks for panics and memory faults.

- It runs on [AFL++](https://github.com/AFLplusplus/AFLplusplus) through cargo-afl, on stable Rust.
- The seeds are the programs in `tests/cases/vm.json`.
- Only programs that parse reach the VM.

> [!NOTE]
> The harness runs the VM with an op budget of 100,000, a thousandth of the sandbox default. A loop that ends but runs long would otherwise read as a hang to AFL.

A campaign runs one instance per logical core until stopped. It needs Linux or macOS and `cargo install cargo-afl`.

> [!COPY] make fuzz

CI runs it back to back, each run starting the next and a schedule every six hours picking the chain up when it breaks, from the corpus the last run kept and on other power schedules each day. A run stops fuzzing 40 minutes before its job's limit by the wall clock, so the minimized corpus and the findings are always saved. A saved crash fails the run.

The crashes and hangs are uploaded as the `fuzz-findings` artifact and kept for 14 days. A local campaign writes them under `fuzz/out/`, one folder per instance.

The [fuzzing manual](https://github.com/dylan-sutton-chavez/edge-python/blob/main/fuzz/README.md) covers container campaigns, resuming, reproducing a crash and triage.

## Miri

[Miri](https://github.com/rust-lang/miri) interprets the test suites and reports undefined behavior and leaks. It runs on the nightly the Makefile pins as `MIRI_NIGHTLY`, which `make miri` installs with the `miri` component before it builds the Miri sysroot.

> [!COPY] make miri SUITE=vm

`SUITE` is one of `vm`, `snapshot`, `modules`, `parser`, `lexer` and `abi`, and `CASE` runs one test of it. CI runs each suite on a runner of its own, a test per core, picking up where the last run stopped. Long corpora run in slices with each case stopped at 5,000 ops, a failed test runs first until it passes, and once every test passes a new round starts in the next mode under a new seed.

## Bench

`make bench` runs every case of `tests/cases/vm.json` on the speed build of `compiler.wasm` and counts the WebAssembly instructions. Each instruction is priced at 0.82 ns. That way `bench/.snapshot` holds the same seconds and MB per case on every machine.

> [!COPY] make bench

The bench fails when the mean or a single case moves past its threshold. It also fails when the snapshot was taken with another Rust, or when a case and its entry do not pair. `make bench-update` takes the snapshot again.

## Consistency

Seeded programs call generated functions cold, again and warm, defined in the main file, in a module and as a method. Every call with the same arguments must answer the same, so code the engine runs differently once it is hot cannot drift. A run checks 500 programs, `EDGE_CONSISTENCY_PROGRAMS` sets more, and a failure keeps its program under the temp dir with its seed.

## Std packages

The tests of every [edge-python-std](https://github.com/dylan-sutton-chavez/edge-python-std) package run on the CLI built from the tree, so an engine change that breaks a published package fails CI.
