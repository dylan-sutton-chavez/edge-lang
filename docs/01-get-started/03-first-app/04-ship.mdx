# Ship the app

`edge build` compiles the program to one native binary. `edge publish` packs the project and every package it declares into one artifact and sends it to the registry, where anyone can add it with `edge add`.

## Name the package

The registry reads the name and the version from the manifest inside the artifact. Add them to `edge.json` with a one line description.

```json
{
  "name": "words",
  "version": "0.1.0",
  "description": "Count the words of a text and rank them.",
  "edge": "0.9.6",
  "imports": {
    "json": "0.1.0",
    "test": "0.1.1"
  }
}
```

A name is first come and permanent. Pick one nobody holds yet. [Package fields](/docs/edge-python/reference/registry#package-fields) lists the rules for each field.

## Build it

> [!COPY] edge build main.py

```text
$ edge build main.py
  compiling main.py for aarch64-apple-darwin...
  (successful) built main
```

`main` runs on its own, with nothing installed. `--wasm` writes a `.wasm` for WASI instead, and `edge web` writes `dist/`, a folder any browser runs, with the JS host and every package beside it.

[edge build](/docs/edge-python/platforms/cli#edge-build) covers the targets and the flags.

## Publish it

1. Create a token in [the settings](https://edgepython.com/settings#tokens).
2. Export it as `EDGE_TOKEN` in your shell.
3. Run `edge publish` in the project.

```text
$ export EDGE_TOKEN=edge_pat_...
$ edge publish
  published words 0.1.0

  add it with  edge add words
  https://cdn.edgepython.com/pkg/words/0.1.0/app.edge
```

The artifact holds the code, the manifest, the lock and both packages. The token signs the request and never leaves your machine. The registry reads the listing out of the artifact itself.

> [!WARNING]
> A published version is never overwritten. Raise `version` in `edge.json` before each new release.
