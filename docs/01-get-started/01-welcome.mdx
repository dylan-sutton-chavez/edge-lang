# Welcome

Edge Lang is an engine for building language runtimes, written in Rust. A single-pass parser compiles source to bytecode with no AST, and a register VM runs it with calls as jumps, an exact memory meter and snapshots. One WebAssembly engine of about 1.6 MB, about 540 KB served as brotli, runs it in browsers, in JavaScript runtimes and in the `edge` CLI.

Edge Lang is the engine, not one language. The parser reads one grammar, spelled by the token table a runtime brings, and what a program means is the runtime's to decide.

The defaults deny everything. A program reaches no files, no network and no environment unless its host grants them. Imports resolve at compile time from `edge.json`, and a running program never loads code you did not declare.

## What a runtime writes

The engine parses, runs, meters and hosts every program, so a runtime writes only what makes it a language. The repo's smallest is `uptime`, a language for checking the services a project depends on. It is the 241 lines of Rust in the five files of `examples/uptime/src`, and its CLI composes the kit in the 23 lines of `examples/uptime/cli/src/lib.rs`. These are all its files.

| File | Lines | Holds |
|---|---:|---|
| `examples/uptime/src/syntax.rs` | 78 | The token table checks are written in |
| `examples/uptime/src/natives.rs` | 23 | Four natives of lib under the names a check calls |
| `examples/uptime/src/language.rs` | 44 | Its rules and the answers lib gives the engine for it |
| `examples/uptime/src/names.rs` | 57 | The classes of its errors and its words for the engine's kinds |
| `examples/uptime/src/lib.rs` | 39 | The front, the descriptor and the wasm exports |
| `examples/uptime/cli/src/lib.rs` | 23 | The CLI composed from the kit |
| `examples/uptime/cli/src/clock.rs` | 38 | A host module of its own that reads the clock |
| `examples/uptime/cli/src/main.rs` | 7 | The binary, with the kit's net plugin |

Its board reads three status pages under the grants of its `edge.json`, and [Your runtime and its CLI](/docs/edge-lang/get-started/use-cases/your-runtime) builds it file by file.

## Who it is for

- **A runtime author** builds a language on the engine. [Your runtime and its CLI](/docs/edge-lang/get-started/use-cases/your-runtime) builds one end to end with a CLI of its own, and the [SDK overview](/docs/edge-lang/sdk/overview) follows a program through the engine and maps every page of the SDK. The [parser kit](/docs/edge-lang/sdk/parser-kit), [Lib](/docs/edge-lang/sdk/lib), [Language](/docs/edge-lang/sdk/language) and the [CLI kit](/docs/edge-lang/sdk/cli) cover its token table, its natives, its rules and errors and its CLI, and [Limits](/docs/edge-lang/sdk/limits) lists what every run is held to.
- **A host** embeds the engine and answers what a program asks of the outside. The [JavaScript host](/docs/edge-lang/platforms/javascript), the [edge CLI](/docs/edge-lang/platforms/cli) and a [Rust host](/docs/edge-lang/platforms/rust) drive the same `edge.wasm`, and [Plugins](/docs/edge-lang/sdk/plugins) covers the host modules they serve.
- **A program writer** runs programs on mini, the reference runtime, with the `edge` CLI. The [Quickstart](/docs/edge-lang/get-started/quickstart) runs a first one.

## Questions

> [!QUESTION] Can a program reach the network or the disk?
> Only what the root `edge.json` grants. Each grant names a module and a scope, such as one host for `net` or one file for `files`, and a program reaches a file only through a `files` grant. [System](/docs/edge-lang/reference/system) lists every scope.

> [!QUESTION] Where does it run?
> The [JavaScript host](/docs/edge-lang/platforms/javascript) runs it in browsers and in runtimes with the same Web APIs, such as Deno. The [edge CLI](/docs/edge-lang/platforms/cli) runs the same engine on macOS, Linux and WSL. [Rust](/docs/edge-lang/platforms/rust) shows how to drive `edge.wasm` from Rust code.

> [!QUESTION] Is there a summary for machine learning models?
> Yes. A model can load `skill/SKILL.md` from the repo for a self-verifying summary of the CLI, imports, permissions, actors and limits.
