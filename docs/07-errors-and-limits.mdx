# Errors and limits

This page covers how compile and run errors read on every host, and every limit of a run and a source.

## Compile errors

A front reports every compile error before anything runs, each with its file, line, column and source line. Lox recovers at the next statement and uses the book's messages.

```lox syntax.lox
var x = = 2;
print "one"
```

```text
$ interpreter run syntax.lox
error: Error at '=': Expect expression.
  --> syntax.lox:1:9
  |
1 | var x = = 2;
  |         ^

error: Error at end: Expect ';' after value.
  --> syntax.lox:3:1
```

In Rust, `FRONT.compile(src)` returns the chunk or the diagnostics, and `Diagnostic::render_all(&errors, src, Some(path))` writes this report. [Where an error is](./04-rust.mdx#where-an-error-is) finds the line and column of a compile or a run error. In a page, `run` resolves with the report in `out`.

## Run errors

An error ends the run. Without a `REPORT` of its own, a runtime gets the engine's report with the class, the message, the line and the calls that led there. Lox sets its own, the message then the line, as the book prints it. The CLI writes the report to stderr and exits with 1, shown as `[exit 1]` on these pages, and `exit(n)` ends a run with status `n`.

```lox broken.lox
fun half(n) {
    return n / 2;
}

print "before";
print half("ten");
```

```text
$ interpreter run broken.lox
before
Operands must be numbers.
[line 2] in script
[exit 1]
```

| Host | Gets |
|---|---|
| Rust | The `Err(e)` of `vm.run()`, which `vm.report_error(&e, src, path)` writes as this report, and `vm.system_exit_code()` for an `exit` |
| JavaScript | `out` of the value `run` resolves with, and `exitCode` |
| `.wasm` | The `ERROR` or `EXIT` kind of the status word, with the report in the output buffer |

A runtime names every error the engine raises through its `Names` and its `message`, so a runtime of yours decides each class and sentence, as [Build a runtime](./02-runtime.mdx#language) shows. A `VmErr` is opaque and the engine's own words are [unspecified](./09-stability.mdx#exceptions), so a host reads an error by its kind.

| Call | Gives |
|---|---|
| `e.kind()` | The `ErrKind` of an engine error, such as `Type`, `Value`, `ZeroDiv` or `Memory`, and `None` for a class a program raised or a signal |
| `e.is_limit()` | Whether the run spent its op budget, its memory or its call depth |
| `e.paused()` | The `SchedulerStatus` of a run that stopped to wait, and `None` for an error |
| `e.is_deferred()` | Whether a host function handed its call back to finish later |
| `VmErr::new(kind, message)` | An error of that kind, for a native or a host function to return |
| `VmErr::raised(text)` | An error as a program raises one, its text written `Class: message` |
| `VmErr::deferred()` | The signal a host function returns to answer its call later |

## Limits

Every run is metered, natives included, and raises an error at the limit it reaches.

| Limit | Default | Set with |
|---|---|---|
| Operations | 100,000,000 | `Limits::sandbox().ops(n)`, `limits.ops` in JS, `--ops`, `set_limits` |
| Memory the run holds | 256 MiB | `Limits::sandbox().memory(bytes)`, `limits.memory` in MiB in JS, `--memory` in MiB, `set_limits` |
| Call depth | The runtime's `recursion_limit`, 1000 in Lox where it reads as `Stack overflow.` | `Policy` |
| Calls nested through a native or a plugin | 128 | Fixed |
| Comparison depth of nested containers | 100 | Fixed |

`Limits::sandbox()` gives the defaults. Memory is an exact count of every byte the allocator hands the run, so a Rust host installs `interpreter::allocator!()` or runs under `Limits::sandbox().memory(usize::MAX)`. A spent op budget cannot be caught, since the handler's first op raises again, and `reset_budget(ops)` gives a stopped run a new one.

```text
$ interpreter run broken.lox --ops 3
Runtime: budget exceeded
[exit 1]
```

A source has these limits, each a compile error.

| Cap | Value |
|---|---|
| Source size | 10 MiB |
| Block depth | 100 |
| Nesting of expressions, targets and patterns | 200 |
| Instructions, names or constants per function | 65,535 |
| Call arguments | 255 positional and 255 keyword |
| Native imports per module | 256 |
| Imports nested one inside the next | 64 |

The engine has no clock, randomness, threads or system access of its own. The same source and input give the same output on `x86_64`, `aarch64` and `wasm32`, and only the host modules a grant opens can differ.
