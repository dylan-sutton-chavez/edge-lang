# Rust

This page covers running programs inside a Rust program. The program links the engine and a runtime and runs them in its own process, with no `.wasm` in between. The examples run Lox from `examples/lox`, and a runtime of yours exposes the same `RUNTIME` and `FRONT`, as [Build a runtime](./02-runtime.mdx) shows.

```toml
[dependencies]
interpreter = { git = "https://github.com/dylan-sutton-chavez/interpreter", branch = "main" }
interpreter-lox = { git = "https://github.com/dylan-sutton-chavez/interpreter", branch = "main" }
```

Lox is not on crates.io, so the engine comes from the same commit, as [Lox](./01-overview.mdx#lox) says.

## Run a program

`FRONT.compile(src)` parses and folds a source and returns the chunk or every diagnostic it found. `FRONT.compile_with(src, resolver)` does the same with the resolver its imports go through. These two calls are the one way to compile. `VM::with_runtime` boots a VM over the chunk and `run` runs it to the end.

```rust standalone_crate
use interpreter::{Limits, VM};

// the memory limit counts what this allocator hands out
interpreter::allocator!();

fn main() {
    let src = "fun square(n) {\n    return n * n;\n}\n\nfor (var n = 0; n < 4; n = n + 1) print square(n);\n";
    let chunk = interpreter_lox::FRONT.compile(src).unwrap_or_else(|errors| panic!("{}", interpreter::Diagnostic::render_all(&errors, src, Some("main.lox"))));
    let mut vm = VM::with_runtime(&interpreter_lox::RUNTIME, &chunk, Limits::sandbox());
    vm.run().expect("the program runs");
    assert_eq!(vm.output_text(), "0\n1\n4\n9\n");
}
```

`interpreter::allocator!()` goes once in the binary. A VM whose limits cap memory refuses to run without it. `output` holds what the program printed, one line per entry, and `output_text()` joins it. `vm.print_hook = Some(f)` takes each text as it is printed instead.

| Call | Does |
|---|---|
| `VM::with_runtime(&RUNTIME, &chunk, limits)` | Boots a machine. The chunk outlives it |
| `run()` | Runs the program, or carries a parked run on |
| `push_event(text)` | Hands an event to a run waiting in `receive()`, or queues it |
| `inject_host_result_by_id(id, value)` | Answers a host call the run waits on |
| `call_export(name, args)` | Calls a function the program defined, after `run` |
| `set_preempt_interval(n)` | Stops the run every `n` loop back-edges, never at 0 |
| `reset_budget(ops)` | Gives the run a fresh op budget |
| `set_input(lines)` | The lines `input()` reads |
| `error_text(&e)`, `report_error(&e, src, path)` | An error as one line, or as the whole report with its source line |
| `display(v)`, `repr(v)` | A value as the runtime prints it |
| `memory()`, `memory_peak()` | What the run holds now, and the most it held |

## What a read keeps

A tool reads a source to map its code back to the bytes it came from. `Front::spelled::<Recorded<S>>().compile(src)` parses a source through table `S` and gives the same chunk as `Front::spelled::<S>()`, and keeps beside the code what its run never reads. A compile keeps none of it, so it costs no more for the read. A front of its own reads by building through `build::<Recorded<S>>` and handing each node to `Builder::spanned(range, kind, f)`, as `interpreter_lox::read(src)` does. The instructions and opcodes of a chunk are not part of the stable API, and a tool reads a chunk through its spans and notes.

| Ask | Gives |
|---|---|
| `body.span(ip)` on any body | The bytes instruction `ip` came from, the operator, name, literal, call, `.` or `[` trailer, or the word that opens its statement or form, and an empty span at the end of a body for the return it closes with |
| `chunk.notes().outline` on the root | Every form in source order as a `Node` with its `kind`, `span` and `parent`, where `parent` is the place of the node around it |
| `chunk.notes().annotations` | Each annotation as a byte `span` and what it annotates, `Annotated::Param { function, name }`, `Annotated::Returns { function }` or `Annotated::Binding { target }`, where `function` is the place of its `Function` node |
| `chunk.notes().decls` | Each `fn`, `let` and `type` item of a [grammar](./03-grammar.mdx), with its `kind`, its `name`, the `span` from its first modifier through its name, the `modifiers` before it and its `node` |

A `NodeKind` names the form.

| Kind | Form |
|---|---|
| `Call`, `Field`, `Index` | `f(x)`, `a.b` and `a[b]` with the operand they follow |
| `Group`, `Tuple`, `List`, `Map`, `Record` | Parentheses that only group, a tuple, a list, a literal in braces and a grammar's record of named values |
| `Let`, `Assign` | A binding word or item, `let _ = e` too, and an assignment |
| `Block`, `If`, `Match`, `Loop`, `Function`, `Type` | A body in braces or indented, the conditionals, the loops, the functions and closures, and the types |
| `Form(head)` | A form a grammar declares, by its head word |

Lox reads through a tree of its own, so a form's own instructions take the whole form, a method's node starts at its name and a function body is no `Block` of its own.

## Where an error is

A diagnostic and a run error hold byte offsets. `Diagnostic::line_col(src)` gives the line and column a diagnostic starts at, counted from 1 with the column as its report prints it. `VM::error_line_col()` gives the same for the last error of a run in the source it rose in, and `VM::error_path()` names the module when that source is one the program imported. `interpreter::Lines::new(src)` finds the lines of a source once, so `line_col(byte)` on it answers many offsets without reading the source again.

```rust standalone_crate
use interpreter::{Limits, VM};

interpreter::allocator!();

fn main() {
    let src = "var a = 1;\nprint a +;\n";
    let Err(errors) = interpreter_lox::FRONT.compile(src) else { panic!("a missing operand is an error") };
    assert_eq!(errors[0].line_col(src).0, 2);

    let src = "var a = 1;\nprint a + nil;\n";
    let chunk = interpreter_lox::FRONT.compile(src).expect("compiles");
    let mut vm = VM::with_runtime(&interpreter_lox::RUNTIME, &chunk, Limits::sandbox());
    vm.run().expect_err("a number and nil do not add");
    assert_eq!(vm.error_line_col().map(|(line, _)| line), Some(2));
    assert_eq!(vm.error_path(), None);
}
```

## Events

A run that calls `receive()` with nothing queued stops, and `run` returns an error whose `paused()` is `Some(SchedulerStatus::PendingEvent)`. Push an event and call `run` again to go on from there. A `VmErr` is opaque, and a host reads it through `kind()`, `paused()`, `is_limit()` and `is_deferred()`.

```rust standalone_crate
use interpreter::{Limits, SchedulerStatus, VM};

interpreter::allocator!();

fn main() {
    let src = "var words = \"\";\nvar m = receive();\nwhile (m != \"stop\") {\n    words = words + m;\n    m = receive();\n}\nprint \"got \" + words;\n";
    let chunk = interpreter_lox::FRONT.compile(src).expect("compiles");
    let mut vm = VM::with_runtime(&interpreter_lox::RUNTIME, &chunk, Limits::sandbox());
    let mut events = ["ab", "cd", "stop"].into_iter();
    loop {
        match vm.run() {
            Ok(_) => break,
            Err(e) if e.paused() == Some(SchedulerStatus::PendingEvent) => vm.push_event(events.next().unwrap()).unwrap(),
            Err(e) => panic!("{}", vm.report_error(&e, src, Some("main.lox"))),
        }
    }
    assert_eq!(vm.output_text(), "got abcd\n");
}
```

## Host functions

A `Resolver` answers each `import("name")`. `Resolved::code(src, canonical)` serves the source of a module and `Resolved::native(canonical, bindings)` serves Rust functions, with `.classes(..)` and `.consts(..)` for more. A function that returns `VmErr::deferred()` stops the run with `PendingHostCall`, and the host answers it later by id. Ids count from 0 in the order the run made its calls.

```rust standalone_crate
use interpreter::{Limits, NativeBinding, Resolved, Resolver, SchedulerStatus, VM};
use interpreter::native::Script;
use interpreter::{Val, VmErr};
use interpreter::value::HeapPool;

interpreter::allocator!();

// a Lox number is a double
fn double(_: &mut HeapPool, args: &[Val], _kw: Option<Val>) -> Result<Val, VmErr> {
    Ok(Val::float(args[0].as_float() * 2.0))
}

// answered later, the way a host waits on a network reply
fn fetch(_: &mut HeapPool, _args: &[Val], _kw: Option<Val>) -> Result<Val, VmErr> {
    Err(VmErr::deferred())
}

struct Host;

impl Resolver for Host {
    fn resolve(&mut self, spec: &str) -> Result<Resolved, String> {
        match spec {
            "host" => Ok(Resolved::native("host", vec![NativeBinding::from_fn("double", double), NativeBinding::from_fn("fetch", fetch)])),
            "util" => Ok(Resolved::code("fun greet(n) {\n    return \"hi \" + n;\n}\n", "util")),
            _ => Err(format!("no module '{spec}'")),
        }
    }
}

fn main() {
    let src = "var host = import(\"host\");\nvar util = import(\"util\");\nprint text(host.double(21)) + \" \" + util.greet(\"ana\");\nprint host.fetch() + 1;\n";
    let script = Script::compile(&interpreter_lox::FRONT, "main.lox", src.into(), Box::new(Host)).unwrap();
    let mut vm = VM::with_runtime(&interpreter_lox::RUNTIME, &script.chunk, Limits::sandbox());
    assert_eq!(vm.run().err().and_then(|e| e.paused()), Some(SchedulerStatus::PendingHostCall));
    assert!(vm.inject_host_result_by_id(0, Val::float(41.0)));
    vm.run().unwrap();
    assert_eq!(vm.output_text(), "42 hi ana\n42\n");
}
```

## Host data

The heap of a machine keeps one value of any type for its natives. A host sets it with `vm.heap_mut().set_data(value)`. A native of the runtime reads it with `cx.heap().data::<T>()` or `cx.heap_mut().data_mut::<T>()`, and a function a `Resolver` serves reads it on the heap it is handed, with `heap.data_mut::<T>()`. Each machine keeps its own, so two machines on one thread never share it, and `vm.heap_mut().take_data::<T>()` gives it back. A snapshot does not hold it.

```rust standalone_crate
use interpreter::{Limits, NativeBinding, Resolved, Resolver, VM};
use interpreter::{Val, VmErr};
use interpreter::lang::ErrKind;
use interpreter::value::HeapPool;

interpreter::allocator!();

// what the host counts for one machine
struct Calls(f64);

fn count(heap: &mut HeapPool, _args: &[Val], _kw: Option<Val>) -> Result<Val, VmErr> {
    let calls = heap.data_mut::<Calls>().ok_or_else(|| VmErr::new(ErrKind::Runtime, "no counter kept"))?;
    calls.0 += 1.0;
    Ok(Val::float(calls.0))
}

struct Host;

impl Resolver for Host {
    fn resolve(&mut self, spec: &str) -> Result<Resolved, String> {
        match spec {
            "host" => Ok(Resolved::native("host", vec![NativeBinding::from_fn("count", count)])),
            _ => Err(format!("no module '{spec}'")),
        }
    }
}

fn main() {
    let src = "var host = import(\"host\");\nhost.count();\nprint host.count();\n";
    let chunk = interpreter_lox::FRONT.compile_with(src, Box::new(Host)).expect("compiles");
    let mut vm = VM::with_runtime(&interpreter_lox::RUNTIME, &chunk, Limits::sandbox());
    vm.heap_mut().set_data(Calls(0.0));
    vm.run().unwrap();
    assert_eq!(vm.output_text(), "2\n");
    assert_eq!(vm.heap_mut().take_data::<Calls>().map(|c| c.0), Some(2.0));
}
```

## Exported functions

After `run` binds the program's names, `call_export` calls one of its functions with values the host built.

```rust standalone_crate
use interpreter::{Limits, VM};
use interpreter::Val;

interpreter::allocator!();

fn main() {
    let chunk = interpreter_lox::FRONT.compile("fun area(w, h) {\n    return w * h;\n}\n").expect("compiles");
    let mut vm = VM::with_runtime(&interpreter_lox::RUNTIME, &chunk, Limits::sandbox());
    vm.run().unwrap();
    let got = vm.call_export("area", &[Val::float(6.0), Val::float(7.0)]).unwrap();
    assert_eq!(vm.display(got), "42");
}
```

## Host values

A host builds and reads values through the heap and never through its storage. `Val::none()`, `Val::bool(b)`, `Val::int(n)` and `Val::float(x)` build the inline values, and each has its `is_` and `as_` reader. `Val::int` keeps 48 bits and wraps past them, so a wider int goes through `heap.int(n)`, which boxes it. `heap.new_str(text)`, `heap.new_list(items)` and `heap.new_tuple(items)` build the heap values. `heap.text(v)` reads a string and `heap.items(v)` reads the items of a list or a tuple, and each gives `None` for a value of another kind.

## Snapshots

`interpreter::snapshot::save` turns a stopped run into a blob, and `interpreter::snapshot::restore` resumes it on a fresh VM over the same program, on this machine or another. The blob holds the heap, every frame and the input not yet read.

```rust standalone_crate
use interpreter::{snapshot, Limits, SchedulerStatus, VM};

interpreter::allocator!();

fn main() {
    let src = "var seen = \"\";\nvar m = receive();\nwhile (m != \"stop\") {\n    seen = seen + m;\n    m = receive();\n}\nprint seen;\n";
    let chunk = interpreter_lox::FRONT.compile(src).expect("compiles");
    let mut vm = VM::with_runtime(&interpreter_lox::RUNTIME, &chunk, Limits::sandbox());
    assert_eq!(vm.run().err().and_then(|e| e.paused()), Some(SchedulerStatus::PendingEvent));
    vm.push_event("a").unwrap();
    assert_eq!(vm.run().err().and_then(|e| e.paused()), Some(SchedulerStatus::PendingEvent));
    let blob = snapshot::save(&vm, src, "main.lox").unwrap();
    drop(vm);

    // a new machine over the same program picks up where the first one parked
    let mut later = VM::with_runtime(&interpreter_lox::RUNTIME, &chunk, snapshot::limits_of(&blob).unwrap());
    snapshot::restore(&mut later, &blob).unwrap();
    later.push_event("b").unwrap();
    later.push_event("stop").unwrap();
    later.run().unwrap();
    assert_eq!(later.output_text(), "ab\n");
}
```

`set_preempt_interval(n)` stops a run that never waits with `SchedulerStatus::Preempted`, so a long loop can be saved too. `snapshot::entry_of(&blob)` returns the script name the blob was saved under.

`snapshot::format_of(&blob)` reads the format word of a blob. An engine restores only a blob of its own `snapshot::FORMAT` and refuses another with an error that says whether the blob is newer or older, so a host can check a blob before it hands one over. [Stability](./09-stability.mdx#formats-and-the-abi) says what the format promises.

## A native binary

`interpreter::native` is a whole host. `Script::read` compiles a file and reads its relative imports beside it, `boot` gives a VM that prints to stdout and reads stdin, and `main` puts both together over the runtime's own front. This is the whole `main.rs` of the `lox` binary.

```rust no_run standalone_crate
use interpreter::Limits;
use std::process::ExitCode;

interpreter::allocator!();

// runs the Lox file its first argument names
fn main() -> ExitCode {
    interpreter::native::main(&interpreter_lox::RUNTIME, Limits::sandbox())
}
```

`main` exits with the statuses the runtime's `Descriptor` gives in `statuses`, and prints compile errors through its `diagnosed` when it sets one. A snapshot error is an opaque `snapshot::SnapErr` that prints its words. A native script loads no URL and no plugin, which the CLI and the JS host do.
